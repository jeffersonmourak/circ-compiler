## 2026-05-06 — Phase 1 — Slice 3: `preview.dump.dump` implementation

**What shipped:** New `lib/preview/dump.zig` exporting `pub fn dump(writer: anytype, topology: full_format.FullTopology) !void`. Pure formatting function (no allocator, no I/O beyond the writer). Two-section output: header (`Topology (v0.full)` + counts) → `Components:` table (id-ascending order, format `[id] kind "name" [origin: chain]`) → `Connections:` table (input order, format `src_id.out -> dst_id.<port_name>`). Origin chains use ` > ` as frame separator with each frame as `alias:subcircuit`; anonymous-alias frames render with empty alias between separators (e.g. `g:xnor > :xor`). `target_file` is omitted from output (debug aid, not user-facing useful). Component kinds rendered via `@tagName` (`input_pin`, `not_gate`, `and_gate`, `led`, `wire`, `output_pin`). Port names decoded via `full_format.PortName` — `in=0, a=1, b=2, out=3`.

Three-step algorithm: (a) compute wire transitive closure — for each `wire` primitive, walk the driver chain back to a non-wire source, recording the resolution in a hash map; (b) determine groups (opaque mode only) — primitives sharing the same outermost `OriginFrame` (alias + subcircuit) cluster into groups, each gets a synthetic id allocated above `max(component.id) + 1`; (c) walk connections, applying wire-resolution to sources and group-remapping to both endpoints — internal connections (both endpoints in the same group) are dropped; surviving connections become `InputEdge` / `OutputEdge` entries on the appropriate `VirtualNode`'s edge lists. Final pass materializes `VirtualNode`s sorted by id ascending: non-grouped primitives become `kind = .primitive(comp.kind)` with their real id and full origin chain; each group becomes a single `kind = .subcircuit(<subcircuit>)` virtual node with the alias as `name`, empty origin chain (the outer frame is "consumed" by the collapse), and the synthetic id.

**Files touched:** `lib/preview/layout/collapse.zig` (new — algorithm + 4 unit tests); `build.zig` (new `preview_layout_collapse_mod` registration with imports for `full_format`, `layout`, `layout_types`).

**Tests:** added `collapse_drops_wire_primitives` (3 components `pin → wire → led` with 2 connections; verifies wire is dropped and a direct `pin → led` edge remains); `collapse_chains_of_wires` (5 components with 3-wire chain; verifies transitive closure works through arbitrarily long chains); `collapse_opaque_subcircuit` (4 components with 2 inside an `xor:g` group; verifies (a) one virtual node with synthetic id 4 is created, (b) `kind = .subcircuit("xor")`, `name = "g"`, (c) internal `not → and` connection vanishes, (d) external connections remap to/from the virtual node, (e) `next_id` is one past the synthetic); `collapse_expanded_subcircuit` (same shape, `expand_macros = true`; verifies all four primitives appear separately preserving real ids and full origin chains, all three connections survive). Ran `zig build test`, result pass — 165+ tests across all suites.

**Next slice:** Phase 2 Slice 3 — Stage 2 (`columns.zig`): longest-path layering. `pub fn assignColumns(arena, graph) !ColumnAssignment`. Input pins force column 0; LEDs/output_pins land in `num_columns - 1`; everything else is `1 + max(column_of[upstream])`.

**Notes:** All collapse-stage allocation is arena-routed (HashMap inits and ArrayList appends use the caller-supplied arena). No explicit deinit calls — arena cleanup is the discipline. The wire-resolution depth is capped at 64 to prevent infinite loops on (theoretical) wire cycles; real `.circ` sources shouldn't produce cycles, but defensive bounding is cheap insurance. The "outer frame consumed" design choice — virtual subcircuit nodes carry empty origin rather than the deeper frames — is deliberate for slice 2: simplifies edge accounting and matches what opaque-mode rendering will need (display the box as `[xor:g]` not as `[xor:g] (containing or:o, nand:n)`). If a future phase wants nested-opaque rendering (collapse only the outermost level, keep deeper levels expanded inside), the algorithm would need to preserve `comp.origin[1..]` on the virtual node — flagged here as a future option, not implemented now. Edge port info is preserved verbatim (the destination port byte from each source connection becomes the virtual node's `dst_port` for that input). Slice 5 (place) may want to remap to per-subcircuit published port names ("a", "b" for xor's published inputs) — but slice 2 keeps it simple.

## 2026-05-06 — Phase 2 — Slice 3: Stage 2 (columns)

**What shipped:** New `lib/preview/layout/columns.zig` with `pub fn assignColumns(arena, graph) !ColumnAssignment`. Longest-path layering algorithm: input pins pinned at column 0; every other node assigned `column_of[n] = 1 + max(column_of[upstream])` via a fixed-point sweep over all nodes (bounded at `n + 1` iterations); after convergence, `led` and `output_pin` primitives are forced to `num_columns - 1` so all sinks line up on the right edge. Returns `ColumnAssignment { column_of, num_columns }`.

**Files touched:** `lib/preview/layout/columns.zig` (new — algorithm + 4 unit tests + helper functions `isInputPin` / `isSink`); `build.zig` (new `preview_layout_columns_mod` registration).

**Tests:** added `columns_longest_path` (4-node chain `pin → not → and → led` produces columns `[0, 1, 2, 3]`); `columns_diamond` (4-node fan-out + fan-in with one pin driving two parallel `not`s feeding one `and` produces `[0, 1, 1, 2]` — verifies parallel paths share the same column); `columns_input_pins_at_zero` (two unrelated input pins both at column 0 — verifies the input-pin pinning rule applies regardless of graph shape); `columns_leds_rightmost` (5 nodes where one LED is "deep" at natural column 3 and another LED would naturally land at column 1 from a direct pin connection — verifies both LEDs get forced to the rightmost column 3, while non-sink nodes keep their natural columns). Ran `zig build test`, result pass — 169+ tests across all suites.

**Next slice:** Phase 2 Slice 4 — Stage 3 (`rows.zig`): barycenter-method row assignment with two sweeps (left-to-right then right-to-left), with deterministic tie-break by ascending node id when barycenter values are equal.

**Notes:** The fixed-point sweep is intentionally simple: O(n²) worst case (each pass touches every node, up to n+1 passes). For the typical `.circ` scale of <50 components, this is fine and the code stays trivially correct. A topological-sort-based one-pass algorithm would be O(V+E) but harder to test. The "force LED to rightmost" rule has a real visual consequence: an LED whose natural longest-path column would be 1 (e.g. a direct `pin → led` connection in a graph that also has a long `pin → not → not → and → led` chain) gets stretched out to the rightmost column. The `columns_leds_rightmost` test specifically exercises this case — without the forced rule, the early LED would land mid-graph and break the schematic's right-aligned-outputs convention. The cycle-handling decision (per the spec's TODO) is silently "iteration cap fires without convergence" — no error returned. Combinational `.circ` sources can't produce graph cycles via subcircuit expansion in the current language, so this is acceptable; if a future feature introduces cycles (e.g. latches), columns will need explicit cycle detection.

## 2026-05-06 — Phase 2 — Slice 4: Stage 3 (rows)

**What shipped:** New `lib/preview/layout/rows.zig` with `pub fn assignRows(arena, graph, columns) !RowAssignment`. Barycenter-method row assignment with two sweeps. Initial row order within each column is id-ascending (inherited from `VirtualGraph.nodes`'s collapse-stage sort). Sweep 1 (left-to-right): for columns 1..N-1, compute each node's barycenter as the mean row of its upstream neighbours from earlier columns, reorder the column ascending barycenter, ties broken by ascending node id. Sweep 2 (right-to-left): same but using downstream neighbours from later columns, processing columns N-2..0. Determinism is anchored on stable input order (`graph.nodes` is sorted by id), float comparison without epsilon, and integer-id tie-break.

**Files touched:** `lib/preview/layout/rows.zig` (new — algorithm + 2 unit tests + helper functions `sweepBarycenter`, `computeBarycenter`, `accumulateRow`, `lessByBarycenterThenId`); `build.zig` (new `preview_layout_rows_mod` registration).

**Tests:** added `rows_barycenter_simple: crossing edges resolved` (4 nodes across 2 columns where naive id-ascending produces crossing edges; verifies barycenter sweep reorders column 1 to eliminate the crossing — `not_a` driven by `pin1` ends up at row 1, `not_b` driven by `pin0` ends up at row 0); `rows_deterministic_tie_break: equal barycenters resolve by ascending id` (3 nodes where two nots in column 1 share the same single upstream pin, so both have barycenter 0; verifies tie-break puts `not_lo` at row 0 and `not_hi` at row 1, plus runs the algorithm twice on the same input to confirm byte-identical row_of and num_rows). Ran `zig build test`, result pass — 171+ tests across all suites.

**Next slice:** Phase 2 Slice 5 — Stage 4 (`place.zig`): per-kind cell sizing + absolute (x, y) coordinate computation + per-component port-coordinate resolution producing `PortSlot` lists. Output: `[]PlacedComponent`.

**Notes:** Hit one implementation mistake in `computeBarycenter`'s first draft: copied neighbour ids into a `std.heap.page_allocator`-backed ArrayList and then tried to free the *items slice* directly, which is wrong (you free the ArrayList's backing buffer via `deinit`, not its `.items` slice). Refactored to inline the iteration over `node.inputs`/`node.outputs` via a small `accumulateRow` helper that takes `&sum` and `&count` pointers. This is the cleaner version anyway — no transient allocation, just a switch over direction. The barycenter iteration uses **linear scan** to find a neighbour's row (`for (buckets[neighbour_col].items, 0..) |bi, pos| if (bi == neighbour_idx) ...`). For the typical `.circ` scale with <50 components per column, this is fine; a future optimization could maintain a parallel `row_of` map updated in lockstep with bucket reorderings, but slice 4 keeps it simple. The two-sweep convergence is good enough for the test cases here; harder graphs (multi-level fan-in/fan-out with high crossings) might need 3+ sweeps to fully minimize crossings, but the spec said "two sweeps" and the tests pass — flagged as a future tunable if Phase 3's render reveals layout sub-optimality.
