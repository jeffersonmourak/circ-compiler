## 2026-05-06 — Phase 0 — Slice 4: IR-walking serializer for `circ.topology.v0.full`

**What shipped:** `lib/topology/full_serializer.zig` gained `pub fn buildFromProject(allocator, project) !FullTopology` (in-memory walk producing a typed topology) and `pub fn serializeProjectFull(allocator, project) ![]u8` (build + encode shorthand for the emit path that slice 5 will call). The walk mirrors `lib/topology/serializer.zig:expandModule`'s recursion structure so the two serializers produce identical global-id sequences (a reader can zip records by index across the two payloads). On top of that, the full walker threads an `OriginFrame` stack through recursion: pushes a frame on entry into a `sub_circuit_ref`, pops on return, and when emitting a primitive, copies the current stack into the component's `origin` chain.

**Files touched:** `lib/topology/full_serializer.zig` (added IR-walk implementation: `ExpanderState`, `BoundInput`, `freePartialComponents`, `dupOrigin`, `parsePortByte`, `primitiveToKind`, `findComponent`, `resolveSignalGlobalId`, `expandModule`, `buildFromProject`, `serializeProjectFull` — plus new `ir` import). `build.zig` (added `ir_types` import to `topology_full_serializer_mod`).

**Tests:** added `full_walk_primitives_have_empty_origin` (hand-built single-module project with three primitives — confirms primitive walk path produces empty origin chains and copies `instance_name` to `name`); `full_walk_one_subcircuit_records_origin` (root referencing a subcircuit via instance "combine" of imported "MyNot" — confirms one-frame origin chain with correct alias/subcircuit/target_file fields); `full_walk_nested_subcircuits` (three-level nesting: root → Wrapper → Tiny — confirms two-frame origin chain in outermost-first order). Ran `zig build test`, result pass.

**Next slice:** Phase 0 Slice 5 — wire the full serializer into the emit path. `cmd/circ-compile/main.zig` will call `full_serializer.serializeProjectFull` (or `serializeModule` for single-file) alongside the existing `serializer.serializeProject`, and `lib/topology/section_writer.zig` gains a `combineTwo` (or similar) entry point so both `circ.topology.v0.min` and `circ.topology.v0.full` are appended to the produced `.wasm`. Plus the integration test that compiles a real `.circ` fixture using a subcircuit and asserts both sections are present and the full payload's origin chain references the subcircuit alias.

**Notes:** The "two parallel serializers must produce identical id sequences" invariant is currently a documented contract, not an enforced one. Slice 5's integration test will exercise it indirectly (decode both sections, assert component IDs match). If a future change to either walker's traversal order breaks the invariant silently, the symptom would be wrong wires in the rendered preview rather than a test failure — worth keeping in mind for slice 5's test design. Resolved the spec's TODO about choosing approach (a) vs (b): went with (b), parallel implementations, because `serializer.zig`'s 80-line `expandModule` is heavily intertwined with payload writing and extracting a generic visitor would be a meaningful refactor risk for this slice's scope. The `serializeModule` (single-file) entry point on the full-serializer side is deferred to slice 5 if needed — the existing `serializeModule` in the min serializer errors on `sub_circuit_ref` so the single-file path on the full side might be unused in practice, but slice 5 will check.
