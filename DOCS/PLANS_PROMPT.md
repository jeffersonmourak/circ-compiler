# Plan Prompt — Layout rewrite (placement and routing for the ASCII preview and the renderer)

## What Is Being Built

The preview layout pipeline (`lib/preview/layout/{collapse,columns,rows,sizing,place,route,orchestrator}.zig`, consumed by `lib/preview/render.zig`, by `circ-compile --preview`, and by the site's Preview tab through `circ_preview` in `site/public/wasm/libcirc.wasm`) draws unrelated wires on top of each other. `tests/fixtures/preview/renders/and_of_not.render.golden` pins the reported case today — `a`'s output and `b`'s vertical meet at a `┬` and share the row into `AND.b` although they are different nets:

```
╭───╮     ╭───╮     ╭───╮     ╭─────╮
│ a ├○┬──▶┤NOT├○╮ ╭▶┤   │ ╭──▶┤ out │
╰───╯ │   ╰───╯ │ │ │AND├○╯   ╰─────╯
      ├─────────┴─┴▶┤   │
      │             ╰───╯
      │
╭───╮ │
│ b ├○╯
╰───╯
```

The cause is structural, not a bug in one branch. The current design places boxes on a fixed grid (`COL_GUTTER = 5`, `ROW_GUTTER = 1` in `place.zig`; per-row heights applied uniformly across columns) and then routes each wire greedily as an L through a gutter that is the same width whatever the demand — `stress_grid_10x10` puts 100 gates in one column and 20 input trunks through the same three usable channel columns. An incremental attempt to fix it (branch `layout-v1-attempt`, four phases of occupancy-aware detours, track bookkeeping and a junction picker, archived as history and not merged) got the reported fixtures clean and drove the corpus count of shared cells from 6,192 to 5,493, but every rule it added was a patch on a router that has no global view: strict occupancy tripled body crossings, refusing vertical sharing doubled shared cells in dense fixtures, and a radius cap made things worse at two radii. The human's verdict was to rewrite placement and routing rather than keep patching.

This initiative replaces the four stages after `collapse` with a layered-graph layout in the Sugiyama tradition as practised by ELK Layered and by Sander's hierarchical Manhattan layout: long edges get dummy nodes so every inter-column gap knows every wire that crosses it; ordering minimises crossings with port positions taken into account; coordinate assignment aligns each node with the ports it is wired to so straight wires are the common case; and routing is done per channel, globally, with as many tracks as the channel needs and a proof that no two nets ever share a same-orientation cell. The same algorithm is then ported to `circ-renderer`'s `src/layout/` so the canvas and the ASCII preview agree byte for byte on a `LayoutGrid`, checked by a JSON conformance harness over the whole fixture corpus. The `LayoutGrid` contract (`lib/preview/layout.zig`: `PlacedComponent`, `RoutedWire { segments, crossings }`, `width`, `height`) and the render stage stay as they are, so `render.zig`, `canvas.zig`, the renderer's painter and every consumer above them do not change.

Definition of done, all of it checked by tests rather than by eye except one gallery review: (1) over every fixture-mode in the corpus, zero wire cells inside a component body, zero cells shared by same-orientation legs of two different nets, zero three-armed `┼`, and every net a tree whose taps are the only junctions — asserted as hard invariants, not as a ratchet; (2) the renders of `and_of_not`, the `demux_*` family, `full_adder_from_builtins` (expanded), `regression_led_out_drives_gate`, `parallel_leftward_detours`, `clean_gated_feedback` and `stress_grid_10x10` are reviewed by the human once and pinned as goldens; (3) `circ-renderer`'s `buildLayout` equals circ-compiler's JSON dump for every fixture-mode with no ledgered divergence left; (4) `zig build test-all` green, `site/public/wasm/libcirc.wasm` and the example previews regenerated from the same revision, the renderer pin bumped, and `DOCS/preview.md` describing the algorithm that ships.

## Architectural Constraints

- **The `LayoutGrid` contract is frozen.** `PlacedComponent { id, kind, name, origin, x, y, width, height, in_ports, out_port, signal_width, display_label }`, `RoutedWire { src_id, src_port, dst_id, dst_port, segments, crossings }`, `Segment { from, to }` with axis-aligned segments listed source to sink, and `LayoutGrid { width, height, components, wires }` do not change shape. Render, the canvas, `dump.zig`, the renderer's painter and `source-link.ts` all read it. New internal stage outputs (layers with dummies, channel tables) are new types in `lib/preview/layout/types.zig`, never fields on the public grid.
- **`collapse.zig` and `sizing.zig` stay.** Macro collapsing, synthetic subcircuit ids (`max(id)+1` upward), slice/concat folding, box sizes and the per-kind port tables (`and`: `a` at `y+1`, `b` at `y+3`, `out` at `y+2` on the right edge; `not`/pins/leds at the vertical middle; memories `addr`/`din`/`we`/`clk`) are inputs to the new stages, not things they may redefine. A port table change is a render change and is out of scope.
- **Render does not change in the Zig phases.** The junction glyphs (`●` split/merge, `┼` crossing, `○` source, `▶◀▲▼` sinks, the `+` fallback picker) are what `render.zig` already draws from `segments` and `crossings`; the new router owes render a grid in which every `crossings` point is a perpendicular crossing or a fan-out/fan-in tap and nothing else. If a render change turns out to be needed, it is its own slice with its own golden diff, argued in STATUS.
- **Determinism is byte-level and cross-language.** Every tie is broken by ascending `(id, port)` or by input order; no floating point anywhere in the pipeline (barycenters compare as rationals by cross-multiplication); no hash-map iteration order reaches an output (iterate sorted keys or index arrays). The TypeScript port is a transliteration, not a re-implementation: same stage boundaries, same names, same tie-breaks.
- **The harness goes through the library front end.** Conformance and invariant tests build with `libcirc.frontend.run(.project)` + `libcirc.modes.buildTopology` + `buildLayout`, not with a hand-assembled pipeline, so a divergence between the test and the CLI/site is impossible by construction.
- **Every golden-producing `zig build` run step sets `has_side_effects = true`.** The step reads the whole fixture tree and, under `UPDATE_GOLDENS`, writes files; neither is a declared input, so the flag keeps the run-step cache out of the picture. (Phase 0 slice 3 tried to reproduce the silent no-op the attempt blamed on the cache and could not — a test run step was re-executed after a warm run with the flag removed — so the flag is a guard, not a fix for an observed bug.)
- **The corpus invariants are hard gates from the phase that claims them.** Phase 0 records today's counts; Phase 3 flips them to `== 0`; from then on a count above zero fails the suite. There is no ratchet mode after Phase 3.
- **Zig changes follow `CLAUDE.md`:** diagnostic codes untouched (this initiative adds none), `tests/fixtures/expected-*` byte-stable (this initiative touches only `tests/fixtures/preview/**`, `site/src/content/examples.ts` previews and the committed wasm), `build.zig` applied as hunks without `zig fmt` (17 pre-existing trailing-whitespace lines).
- **Git conduct** per `CLAUDE.md`: stage by path, Conventional Commits under 70 characters, no phase or slice prefixes, no trailers of any kind, never push; the renderer repository is a second repository with the same rules and its push is the human's.

**Algorithm background.** The plan is grounded in these sources, read at plan time; the deep planner and the execution agent cite them by name rather than re-deriving:

- Wybrow, Marriott, Stuckey, *Orthogonal Connector Routing* (GD 2009; `libavoid`): an orthogonal visibility graph built from lines projected off object corners and connector ports, an A* search minimising a monotonic function of length and bends with direction-aware states `(v, D)` and a remaining-bends lower bound, then a nudging pass that orders connectors sharing a segment so crossings happen only where paths enter or leave the shared run. https://users.monash.edu/~mwybrow/papers/wybrow-gd-2009.pdf and https://www.adaptagrams.org/documentation/libavoid.html. Marriott et al., *Seeing Around Corners* (Diagrams 2014): obstacle-hugging canonical routes and a one-bend visibility graph. https://users.monash.edu/~mwybrow/papers/marriott-diagrams-2014.pdf.
- Eclipse Layout Kernel, *ELK Layered* (Domrös et al., arXiv 2311.00533; reference page https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html): the five-phase layered pipeline — cycle breaking, layer assignment (network simplex by default, longest path available), crossing minimisation (layer sweep with barycenters and port constraints), node placement (Brandes–Köpf, edge straightening), orthogonal edge routing with hyperedge-aware channel widths from `edgeEdgeBetweenLayers` / `edgeNodeBetweenLayers` / `nodeNodeBetweenLayers` spacing; model order as the deterministic tie-breaker.
- Sander, *A fast heuristic for hierarchical Manhattan layout* (GD 1995): edges between adjacent layers are split into at most three segments; each edge's horizontal run gets a line row from a conflict graph; at most four bends per edge; channel height is the number of line rows used. https://link.springer.com/chapter/10.1007/BFb0021828.
- Brandes, Köpf, *Fast and Simple Horizontal Coordinate Assignment* (GD 2001): vertical alignment of each node with its median neighbour in four directions, horizontal compaction of aligned blocks, balancing of the four results. https://link.springer.com/chapter/10.1007/3-540-45848-4_3.
- Channel routing (Lengauer, *Combinatorial Algorithms for Integrated Circuit Layout*; https://www.ifte.de/books/eda/chap6.pdf; https://sites.lafayette.edu/cadapps/main-page/channel-routing/): the left-edge algorithm assigning nets to tracks by interval packing, the vertical constraint graph, doglegs to break constraint cycles, the greedy channel router.
- McMurchie, Ebeling, *PathFinder: a negotiation-based performance-driven router for FPGAs* (FPGA 1995): iterative rip-up and reroute with a congestion cost `(b(n) + h(n)) · p(n)` that converges to a conflict-free routing. https://dl.acm.org/doi/pdf/10.1145/201310.201328.

**Locked decisions.** Routine calls made at plan time so no slice reopens them. Each phase appends the ones it exercises to a new `DOCS/decisions/preview-layout.md`, registered under Topics in `DOCS/decisions/index.md` (`###` headings, referenced by slug).

1. **Layered layout, not fixed-position connector routing.** Visibility-graph A* (libavoid) is the right tool when node positions are given and immovable; here the layout owns the positions, and a per-connector search is greedy in exactly the way the current router is — each wire is optimal given the ones before it and nothing corrects the order. The rewrite is the Sugiyama pipeline: layering → ordering → coordinate assignment → channel routing. Two pieces of libavoid are reused as design, not code: the nudging rule that nets sharing a channel are ordered so crossings occur only at entry and exit, and A* with a bend penalty as the bounded fallback for a net the channel router cannot place (decision 9).
2. **Stage skeleton and file map.** `collapse.zig` (unchanged) → `layering.zig` (replaces `columns.zig`) → `ordering.zig` (replaces `rows.zig`) → `coords.zig` (replaces `place.zig`) → `channels.zig` (replaces `route.zig`) → `orchestrator.zig`. The old files are deleted in the phase that replaces them, never left beside the new ones. `types.zig` grows `LayeredGraph` (real and dummy nodes per layer, edges as layer-adjacent segments, back-edge flags), `Ordering` (node order per layer), `Coords` (per node `x`, `y`, per column `x`, per channel width) and `ChannelTable` (nets per gap with their tracks). The renderer gets the same files: `src/layout/{layering,ordering,coords,channels}.ts`.
3. **Layering keeps longest path with input pins pinned to layer 0 and root output pins and LEDs to the last layer**, plus the existing DFS cycle breaking (a back edge is reversed for layering and flagged). Network-simplex layering (shorter edges, fewer dummies) is deferred: it changes every golden a second time for a gain the corpus does not yet show it needs. Recorded as an open item, not a slice.
4. **Long edges get dummy nodes.** An edge spanning `k > 1` layers is split into `k` layer-adjacent segments through `k − 1` dummy nodes, one per intermediate layer, width 0 and height 1. Dummies take part in ordering (so a long wire's row is chosen against the real crossings it causes) and in coordinate assignment (so it gets a reserved row through each column it passes). This is the change that ends "gutters blind to the rows they cross": a long edge is a straight horizontal through every intermediate column, at a row nothing else owns, and bends only inside channels. A chain of dummies belonging to one source is one net for the channel router (fan-out to several sinks shares the trunk up to the layer where the sinks diverge).
5. **Ordering is barycenter sweeps with port-aware crossing counts and a transpose pass.** Sweep down and up until a full round improves nothing or four rounds have run; a sweep reorders a layer by the barycenter of its neighbours' *port* rows (an `and`'s `a` and `b` ports are at fixed offsets, so `a` above `b` is a crossing constraint, not a tie); equal barycenters keep the current relative order, and the initial order is ascending id. After the sweeps, a transpose pass swaps adjacent nodes in a layer whenever that reduces the crossing count, repeated to a fixed point. Crossing counting is the bilayer count over edge endpoints' port rows. All arithmetic is integer: a barycenter is `(sum, count)` and comparisons cross-multiply.
6. **Coordinate assignment aligns nodes to the ports they are wired to.** Columns keep their x from cumulative widths, but the gutter after a column is now that channel's computed width (decision 8), not `COL_GUTTER`. Rows are assigned per node, not per grid row: walking layers left to right, each node's preferred y is the one that makes its highest-priority in-edge a straight horizontal (the port row of its median predecessor, Brandes–Köpf's vertical alignment restricted to one direction); nodes in a layer are then packed top to bottom in their order with at least `ROW_GUTTER = 1` free rows between boxes, pushing down only as far as needed; a second pass from right to left aligns sources to their single sink where doing so breaks no earlier alignment. Dummy nodes have height 1 and are aligned with their predecessor's row whenever the packing allows, so a long wire stays straight. The result is deterministic and never exceeds the height of today's grid for a straight chain.
7. **Channels are routed per inter-layer gap with a left-edge track assignment and a constraint graph.** For gap `g` between layer `i` and `i+1`, every edge segment crossing it is a net with one left terminal (a source port row, or a dummy row) and one or more right terminals (sink port rows, or dummy rows) — a source with several sinks in the next layer is one net with one track and `●` taps. A net whose terminals are all on one row is a straight horizontal and takes no track. Otherwise the net gets a vertical track `x` inside the channel, spanning its terminal rows; tracks are assigned by the left-edge algorithm on the nets' row intervals (sorted by top row, first free track whose occupied intervals do not overlap, one blank column between tracks that overlap in rows is *not* required — distinct nets in adjacent tracks are legible). The horizontal constraint: on any row `r` where net A has a left terminal and net B a right terminal, A's track must be strictly left of B's, or their horizontals overlap on `r`; these constraints form the channel's constraint graph and the left-edge order respects it (topological order first, then interval packing). Channel width is the number of tracks plus the two marker cells (`○` on the source side, `▶` on the sink side) plus one, and it is fed back to coordinate assignment (decision 6) — so `COL_GUTTER` is gone and a channel with twenty trunks is twenty-plus cells wide while a channel with one is as narrow as today's.
8. **Constraint cycles are broken by doglegs; the row for a dogleg comes from the channel, never from a box row.** A cycle in the constraint graph (A must be left of B on row `r1`, B left of A on row `r2`) is broken by splitting the net with the longer interval into two tracks joined by a horizontal jog on a row that no net in this channel uses as a terminal; if no such row exists the channel asks coordinate assignment for one spacer row at the position that separates `r1` from `r2`, coordinate assignment inserts it (the whole diagram below shifts down by one), and the channel is routed again. This loop is bounded by the number of nets in the channel and is the only feedback between routing and placement.
9. **Back edges take a return lane.** A flagged back edge (source layer `j` ≥ sink layer `i`) leaves its source into channel `j`'s track set, drops to a return row *below* the lowest box of the layers it spans (one row per back edge, allocated bottom-up in ascending source id order), runs left to channel `i`, and rises to the sink port. Return rows are part of the height, and a return lane's vertical inside a channel is a track like any other, so it cannot share with a forward net. `clean_gated_feedback`, `parallel_leftward_detours` and `regression_led_out_drives_gate` (the leftward `LED.out → AND.a` wire) are the fixtures that pin this; the gallery's `sr-latch` example is the user-facing case. The bounded A* fallback of decision 1 applies only to a net the dogleg loop reports as unplaceable, is limited to the channel's cells, and its use is counted in the invariant report so it never becomes the normal path silently.
10. **Crossings are allowed and minimised; sharing is forbidden and checked.** Two nets may cross perpendicularly (`┼`); a net's tap on its own trunk is `●`; nothing else may touch. The invariant checker (Phase 0) is the definition: I0 wire cells inside a box body; I1 cells covered by same-orientation legs of two different nets; I2 cells where three or more arms of different nets meet; I3 a net whose segments do not form a tree rooted at its source. All four are zero from Phase 3 on for every fixture-mode. Crossing count per fixture is reported (a golden table) and expected to fall, but it is not a gate.
11. **`RoutedWire.segments` and `crossings` are produced by the channel stage in the shape render already expects.** One `RoutedWire` per `(src, dst)` pair as today, segments from the source port cell to the sink port cell, corners included; a fan-out net emits one wire per sink whose segments share the trunk cells (that is how render finds split points). `crossings` lists every cell where this wire's segments cross another wire's perpendicularly, plus the split/merge points, computed from the channel table rather than by pairwise `segmentCross` over all wires.
12. **The JSON conformance contract is the one `layout-v1-attempt` defined.** Phase 0 revives `lib/preview/dump_json.zig` and `tests/preview/layout_conformance_test.zig` from `git show layout-v1-attempt:…` (`4fb480e` is the commit): camelCase keys, the common-subset projection (`width`, `height`, `components[] { id, kind, name, x, y, width, height, inPorts, outPort, bitWidth }`, `wires[] { srcId, srcPort, dstId, dstPort, segments }`), goldens under `tests/fixtures/preview/layouts-json/`, copied verbatim to `circ-renderer/test/fixtures/layouts/` where `test/layout-parity.test.ts` compares `buildLayout()`. The corpus grows from the attempt's 12 fixture-modes to every fixture the CLI can preview (both modes where a macro exists), enumerated by a build-time walk rather than a hand list.

## Recurring Traps

Add an entry here during execution whenever a non-obvious constraint surfaces — in the same slice that hit it, under the group it belongs to — and name it in that slice's STATUS entry `Notes:` line.

**Build and goldens**

- **Golden-producing test steps declare `has_side_effects = true`** (the conformance and invariant steps in `build.zig`): they read the fixture tree and write goldens, none of it a declared input. Phase 0 slice 3 could **not** reproduce the "cached no-op" the attempt reported (a warm test run step re-ran under `UPDATE_GOLDENS=1` with the flag removed), so do not lean on the flag to explain a golden that did not regenerate — look for an edit that removed the test, or a run that never reached it, first.
- **`build.zig` has no test filter.** `zig test <file>` cannot resolve the module imports of anything under `lib/preview/`; run `zig build test` and read the failing test's name from the output. Budget for the full suite on every iteration.
- **`build.zig` is not `zig fmt`-clean** (17 trailing-whitespace lines). Apply hunks without reformatting; a `zig fmt` pass is its own commit.
- **Render goldens are driven from two harnesses** (`tests/libcirc/driver_test.zig`, `tests/e2e/libcirc_wasm_test.zig`) and the wasm one is skipped in CI (`SKIP_WASM_E2E=1`); run it locally before every golden regeneration or the two can drift.
- **`tests/preview/layout_integration_test.zig` assembles its own pipeline** (scan → resolve → validate → `orchestrator.build`), which is not the CLI's path; leave it as a unit harness for the stages but never treat its five text goldens as the parity contract — the JSON conformance test through `libcirc.frontend.run(.project)` is.

**The algorithm**

- **Fixed gutters are demand-blind; the attempt proved every local rule fails somewhere in the corpus.** Strict occupancy everywhere tripled body crossings; refusing vertical sharing in every detour pass doubled shared cells in dense fixtures; a radius cap made things worse at both 3 and 6; per-bucket track bookkeeping let trunks from different source columns share a column; adjacency-as-hard-rule walked trunks through boxes. Do not re-derive these on the new router — if a channel cannot be routed, the answer is a track, a dogleg or a spacer row (decisions 7–8), never a special case.
- **`and` ports are asymmetric** (`a` at `y+1`, `b` at `y+3`) and `not`/pins are centred at `y+1` on a height-3 box, so a NOT feeding an AND's `b` port cannot be straight unless the NOT sits two rows lower than the AND — this is what the per-node rows of decision 6 exist for and what per-grid-row heights could never do.
- **Collapsed macro boxes have synthetic ids above `max(id)+1`** and their port slots come from `sizing.macroSize`; dummies must use an id space that cannot collide with them (negative or a separate index, never `max(id)+k` computed twice).
- **Floats are forbidden in the pipeline** (decision 5). A `f64` barycenter sorted by `<` is stable across Zig and JS today, but a single `sum / count` rounding difference in a future refactor would break byte parity silently; `(sum, count)` pairs compared by cross-multiplication cannot.
- **Hash maps iterate in insertion-dependent order in Zig and in JS differently.** Any map whose contents reach an output is drained through a sorted key list.

**Cross-repository work**

- **Every renderer command names its directory.** The shell's working directory resets between commands; `cd /Users/jeffersonmourak/circus/circ-renderer && bun test`, never a bare `bun test` after an earlier `cd`.
- **`circ-renderer` has no CI and no build step** (`main` and `module` point at `src/index.ts`); its gate is local, and its `github:` pin resolves only from the remote after the human pushes.
- **The site's Preview tab is `libcirc.wasm`, not the renderer.** A layout change reaches `/playground`'s Preview through `cd site && bun run libcirc`; the renderer pin only moves the Simulate canvas. Both move in Phase 4's last slice so they cannot disagree.
- **`bun run scripts/compile-content.ts` rewrites `site/src/content/examples.ts`'s preview strings** and `scripts/.compiled.json`; expect a large diff there in Phase 4 and stage it by path. It also writes `public/wasm/tour-*.wasm`, which is gitignored.

**Editing discipline**

- **A string replace that does not match is a silent no-op.** On `layout-v1-attempt` a slicing edit deleted the parity tests and the cached run step then hid it. Assert the anchor before writing, and after any edit to a test file re-run and compare the test count to the previous STATUS entry.
- **A proof whose failure mode is "did not run" reads as success.** Negative proofs (inject the bug, watch the test fail) must assert that the injection landed and must check the run for the failure, not for the absence of a pass.
