# Plan Prompt — libcirc (the compiler as a library, in the browser)

## What Is Being Built

`circ-compiler` becomes usable without installing it. The front end that today lives behind `cmd/circ-compile/main.zig`'s mode dispatch is lifted into a library, `lib/libcirc.zig`, that takes an in-memory project (`{ root, files: { "<virtual path>": "<text>" } }`) and returns what each CLI mode returns today — a self-contained `.wasm` artifact, `--analyze` JSON, `--preview` text, a truth table — through one C ABI that is built two ways: `zig build libcirc` (a native static library plus `include/libcirc.h`, so `circ-lsp` could later stop spawning a subprocess) and `zig build libcirc-wasm` (one `wasm32-freestanding` module, `libcirc.wasm`, ReleaseSmall and stripped, embedding the runtime it was built with). The website (`site/`, static Astro, bun-only deploy) gains `/playground`: a Web Worker owns `libcirc.wasm`, a textarea drives analyze/compile/preview/truth-table on a debounce, and the compiled artifact bytes go straight into `circ-renderer`'s existing `bytes:` path for the interactive simulation the examples page already offers — entirely client-side, no server, no CLI.

The one hard blocker is the parser. It is a langlang-generated Go program linked as a CGo c-archive (`lib/parser/parser.a`, `lib/parser/shim/shim.go`, `lib/syntax/CParser.zig`), and there is no route from Go to `wasm32-freestanding`: Go refuses `c-archive` for any wasm platform (`$GOROOT/src/internal/platform/supported.go:146-158`), `parser.h:66` static-asserts 64-bit pointers, and `build.zig:43-53` panics for any non-native target; langlang v0.1.2 generates only Go and a Rust VM. **Locked direction: langlang itself generates the parser straight to Zig.** The user's fork (`~/circus/langlang`, branch `zig-parser-gen`, pinned to upstream `go/v0.0.12` — the exact generator that produced today's `parser.go`) gains `-output-language zig` (plan: `go/zig/PLAN.md` in that repo): one self-contained `parser.zig` = a Zig runtime (a full port of langlang's VM, all 33 opcodes including left recursion, pasted from `go/zig/langlang_runtime.zig`) + the grammar's bytecode as comptime tables + a `Rule` enum, proven byte-identical to the Go VM by a differential harness on the langlang side over langlang's own grammar corpus and over circ's grammar and fixtures. circ vendors that file as `lib/parser/parser.zig` exactly as it vendors `parser.go` today, `lib/syntax/translate.zig` keeps its tree-shape logic and re-targets its six accessors from cgo handles to the Zig `Tree` API, and the 27 `expected-ast` goldens stay byte-identical. Grammar changes remain `edit .peg → zig build parser:gen → review goldens`, and because the runtime is complete and lives with the generator, no future grammar growth requires runtime work in circ. Go, the c-archive, and the Go toolchain prerequisite leave the repo in the same phase the Zig parser lands.

Definition of done: (1) `/playground` compiles, diagnoses, previews, tabulates, and simulates user `.circ` (single-file or `// name.circ` multi-file) with no server; (2) `zig build`, `circ-compile`, and `zig build test-all` pass with only Zig and Node installed, every `tests/fixtures` golden byte-identical (except the additive `Errors (n)` line Phase 0 adds and the site example regeneration in Phase 4), `tests/cli/integration_test.zig` and `tests/e2e/cli_e2e_test.zig` unchanged; (3) `zig build libcirc` and `zig build libcirc-wasm` share one export surface and emit the exact `DOCS/analyze-api.md` JSON; (4) `lib/parser/`, `CParser.zig`, the `go build` step, and the Go prerequisite are gone, and `DOCS/decisions/tooling.md` records why. Sequencing constraint: Phases 0 and 1 touch only `lib/parser`, `lib/syntax`, tests, and the parser steps of `build.zig`, none of which PR #79 (native memories, branch `memories`) modifies, so they start now; **Phases 2–5 start after PR #79 merges** (it rewrites `cmd/circ-compile/main.zig`, `lib/truth_table/builder.zig`, `lib/engine_session.zig`, bumps topology to v03, and adds eight runtime exports — lifting the driver before that lands guarantees a painful conflict and would do the renderer sync twice).

## Architectural Constraints

- `translate.parseSource(allocator, file_id, source) !ast.File` and `parseSourceCapturing(..., ?*ParseFailure)` are frozen signatures (callers: `scan_imports.zig:139`, `resolve_bodies.zig:426`, `analyze.zig:145`, `main.zig:190`, twelve test files). `ast.zig` and `tests/helpers/ast_dump.zig` output are the parser's golden contract; the only permitted dump change is Phase 0's additive `Errors (n)` section.
- The VM reproduces langlang's semantics exactly, quirks included: byte-wise charsets and `span` (`parser.go:1643-1668` — multibyte UTF-8 matched byte by byte, which is what keeps columns and `[^"]` import paths identical); captures discarded on backtrack (`parser.go:1056-1146`); `throw` resolving through `rxps` into the recovery rule and resuming (`:1721-1732`); `newNode`'s collapse rule (`:2007-2060`: 0 children + width → String, 1 child → that child, else Sequence; `rxbs`-flagged captures → Error); root set only when the capture stack is non-empty (`:1844-1849`, so an empty file is `error.ParsingFailed` at `translate.zig:702` and whitespace-only is `error.InvalidProgram` at `:720-723`). Not ported: `ffp`/expected tracking and `mkErr` messages (the hard-failure path is unreachable — `Program`'s `RecoverLine` plus newline-eating Spacing only exit at EOF), the shim's label messages (Zig owns them at `translate.zig:641-648`), and the LR/memo opcodes (`call_lr`/`return_lr`/`cap_return_lr` never appear in the shipped bytecode; the extractor asserts this).
- Every `expected-*` golden stays byte-identical through Phases 1–5. Parser quirks are pinned, not fixed (keyword-prefix splitting `andx g(...)` → `and` + instance `x`; trailing whitespace absorbed into a `BaseRef`; cascaded `busvalue`+`busclose` marks; a width literal > 255 drops the whole declaration; `import x ""` is kept with the path `"`; `output o()` swallows the following line). Fixing them is a later grammar initiative.
- `--analyze` JSON (`DOCS/analyze-api.md`) stays byte-compatible — `circ-lsp` parses it (`circ-lsp/src/analyzer.ts:65-84`); `code: "syntax"` diagnostics keep coming from `analyze.zig:141-176`. libcirc's status-1 result *is* that shape, so the playground and the LSP format one thing.
- Diagnostic codes are append-only (`lib/validator/codes.zig`, `tests/validator/codes_snapshot_test.zig`, `DOCS/decisions/validation.md`); libcirc adds none. `E017`/`E018` arrive with PR #79.
- No allocator parameter on the engine (CLAUDE.md invariant 6; `lib/memory.zig:65-71` global arena). libcirc may add exactly one thing: `memory.reset()` (`arena.reset(.free_all)`), called only with no `Circuit`/`Session` alive.
- Topology versions are owned by `lib/topology/format.zig` and `full_format.zig`; no compatibility shim in the compiler (`DOCS/decisions/compiler-pipeline.md`, pre-1.0 the version byte is freely revvable). The renderer follows the compiler: one commit bumps the `circ-renderer` pin, regenerates `site/public/wasm/*.wasm`, and refreshes `libcirc.wasm` from one compiler revision.
- The runtime's export list stays as `DOCS/decisions/runtime-api.md` records it; `circ_reset` and friends are *library* exports, never runtime exports. `env.debugEnabled`/`env.onDebugLog` remain the only host imports.
- CLI text, exit codes, and parse-time flag gating are frozen (`DOCS/decisions/cli.md`; `tests/cli/integration_test.zig` spawns the binary and itself runs `zig build circ-compile`, `:41-49` — after Phase 1's flip that nested build must not need Go either). The import-free single-module fast path (`main.zig:200-210`, perf-budget tests) is preserved. `--sim`, `--emit-zig`, and `--inspect` stay CLI-only.
- `build_options` is materialised once and imported by module object (`build.zig:720-748`; never call `addOptions` twice). The three consumers (CLI, `libcirc.a`, `libcirc.wasm`) share one module graph through a new `build/frontend_modules.zig` helper.
- Site rules: static output, every internal path through `url()` (`site/src/utils/url.ts:6-9`), no Zig/Go in `deploy-site.yml`, lazy-load everything heavy on first interaction (the `LiveCanvas.astro` pattern).
- Git conduct per `CLAUDE.md`: stage by path, propose every commit message and wait, Conventional Commits titles without phase/slice prefixes, no trailers, never push without an explicit go-ahead.

Locked design decisions (recorded in `DOCS/decisions/tooling.md`, `compiler-pipeline.md`, and a new `libcirc.md` during Phase 5):

1. **Parser: generated to Zig by langlang** (the fork's `-output-language zig`), not a circ-local VM, not a hand-written parser, not a Go sidecar. The runtime is complete (all 33 opcodes) and maintained with the generator, so grammar growth never needs parser work in circ; parity is proven on the langlang side by a differential harness before circ switches. Alternatives recorded in `tooling.md`: a circ-local bytecode VM (would track langlang's instruction set by hand), recursive descent (grammar becomes prose), Go `js/wasm`/`wasip1` sidecar (~2–2.5 MB of Go runtime, two linear memories), wrapping `parser.a` (impossible for wasm).
2. **Pin the contract before switching parsers.** `ast_dump` gains `Errors (n)`; ~12 recovery/quirk fixtures and four `expected-analyze` JSON goldens (clean, truncated, junk-line, empty) are generated by the Go parser and hand-reviewed; circ's fixtures and inline inputs are also fed to the fork's corpus-mode differential test (`go/zig/scripts/diff-circ.sh`) so recovery parity is checked with node ids and spans, not only through goldens.
3. **One wasm module, ten exports, JSON in / bytes-or-JSON out.** `circ_alloc(len)`, `circ_free(ptr, len)`, `circ_version()`, `circ_analyze(req, len)`, `circ_compile(req, len)`, `circ_preview(req, len)`, `circ_truth_table(req, len)`, `circ_result_ptr()`, `circ_result_len()`, `circ_reset()`. Request: `{"root": "/playground/main.circ", "files": {"<path>": "<text>"}, "options": {...}}`. Status: `0` ok (result = artifact bytes / preview text / table text / analyze JSON); `1` front-end diagnostics (result = `{"files":[...],"diagnostics":[...]}` in analyze-api shape); `2` bad request; `3` mode refusal (`{"error": "..."}`: input-bit cap, RAM-stateful truth table after PR #79, layout failure); `4` out of memory; `5` internal. Request buffers come from `circ_alloc` and are freed by the caller; the result buffer is library-owned and valid until the next `circ_*` call. Identical surface for `libcirc.a` (`export fn`, `callconv(.c)`, `u32` ptr/len).
4. **Overlay-first virtual file loading.** `file_loader.resolveImportPath` resolves lexically with `std.fs.path.resolvePosix` (pure, matches how imports are joined today at `:69-70`), returns the key when the overlay holds it, else `realpath` on native, else `FileNotFound` (keeps `E009` at `scan_imports.zig:172-181`); `loadFileWithOverlay` consults the overlay before `realpath`; disk branches are compiled out on `.freestanding`. Keys are absolute-looking virtual paths (`/playground/<name>.circ`), normalised byte-for-byte. This also fixes a latent native bug: overlay-only *sibling* imports fail with `E009` today because `:72` realpaths unconditionally.
5. **Library memory model.** Per-call `ArenaAllocator` for compiler allocations; a library-owned result buffer; `memory.reset()` after `truthTable` tears down its `Session`; on wasm the arena sits over `std.heap.wasm_allocator`. No re-instantiation per call.
6. **`-Dwasm-optimize`** (default ReleaseSmall, stripped) governs `circ-runtime.wasm` and `libcirc.wasm`, decoupled from `-Doptimize` (`build.zig:708-712` ties the runtime to the global option, which is why every committed site artifact is a ~921 KB Debug build, ~600 KB of it DWARF). `expected-wasm` fixtures are behaviour vectors, so the runtime's bytes may change freely; `site/public/wasm` is regenerated in Phase 4.
7. **The renderer follows the compiler**, once, for v03: libcirc is sequenced after PR #79 so the `circ-renderer` sync (kinds 8/9, ports 4..7, `Aux.memory`, an exported `SUPPORTED_TOPOLOGY_VERSIONS`) is done a single time; the playground does a `circ_version().full_version` handshake against that set and shows a banner instead of a decode throw.
8. **Playground artifacts are committed** (`site/public/wasm/libcirc.wasm` + `libcirc.manifest.json` with version, revision, topology versions, grammar sha256, byte size; `site/scripts/build-libcirc.ts` fails over budget), refreshed on tagged releases; the module runs in a Web Worker so `2^bits` truth-table enumeration never blocks the page (UI cap 10 bits, ≤ 12 with a warning; the library's 24-bit maximum is unreachable from the page).
9. **Retire Go in one cut-over, after the fork proves parity.** Phase 1 vendors `parser.zig` and deletes `lib/parser/` (Go source, shim, archive), `CParser.zig`, and the Go build plumbing in the same slice, because the differential proof lives on the langlang side (`diff-circ.sh` at 0 mismatches over circ's fixtures and inline inputs, plus `TestGenZigTablesMatchVendoredGo`) and circ's own goldens are the acceptance; no dual-parser build option in circ. The generated file's header records the runtime sha256 and langlang version, which is the skew signal if the fork and the vendored file drift.
10. **Not exported through libcirc:** `--sim` (stdio-shaped; reads image files on PR #79), `--emit-zig` (needs a Zig toolchain on the consumer, rejects memories), `--inspect` (single-module debug output; `circ_inspect` is a cheap later addition if a debug tab is wanted). Browser interactivity is `circ_compile`'s bytes fed to `renderCircuit({ bytes })`.

Phases are ordered by dependency, not by priority. Each phase must be fully shippable before the next begins.

## Working Loop

The execution agent follows this loop every session without exception:

### On Cold Start

1. Read this file (`DOCS/PLANS_PROMPT.md`) in full.
2. Read `DOCS/STATUS.md` (if it exists). The latest entry defines what was last shipped and what comes next.
3. Run `git log --oneline -10` and `git status`. If STATUS claims a slice is committed but it does not appear in `git log`, the human has not committed yet — **do not begin a new slice**. Stop and say so.
4. Read the active phase plan (`DOCS/PLANS/PHASE_<N>_<name>.md`) for the current phase.
5. Implement the next slice per the phase plan. Do not start a second slice until the first is reviewed and committed.

### Each Slice

1. Implement the full slice as specified. Do not stop mid-slice.
2. Run the project's test command for the affected modules. Do not ship a slice that breaks the suite.
3. Append a STATUS entry (template below).
4. Stage the slice's files (`git add <files>`).
5. Display the proposed commit message and **stop**. Wait for explicit human approval before running `git commit`. Do not begin the next slice until the commit is confirmed and made.

### Git Rules

- Read-only git commands (`status`, `log`, `diff`) are encouraged for situational awareness.
- **Committing:** At the end of a slice — and only at the end of a slice — the agent stages the slice's files (`git add <files>`), then displays the full proposed commit message to the human and waits for explicit approval before running `git commit`. Staging first lets the human inspect the diff in any git client before approving. Do not commit without that confirmation.
- Do **not** push, force-push, amend, rebase, reset, delete branches, or run any other write `git` or `gh` command under any circumstances.

## Recurring Traps

- **Plan-file collision with the memories initiative.** PR #79 carries its own `DOCS/PLANS_PROMPT.md`, `DOCS/PLANS/PHASE_*.md`, and `DOCS/STATUS.md`. When it merges, archive that plan on `main` first (`DOCS/prompts/ARCHIVE.md` → `DOCS/archive/plan-memories.md`) and only then rebase this branch; otherwise the rebase conflicts on all three files.
- **Backtracking must discard captures pushed since the choice frame** (`parser.go:1056-1146`). A `throw` inside an alternative that later fails (Connection → PortRef → AnonDecl → BusType, then a missing `<>`) must leave only the `RecoverLine` mark. The VM gives this for free; a hand port would not.
- **Charsets and `span` are byte-based** (`parser.go:1643-1668`); `[^\n]`/`[^"]` match UTF-8 continuation bytes individually. Keep the VM byte-based or columns and import paths diverge.
- **Trailing whitespace is absorbed into a `BaseRef`** when `('.' Identifier)?` fails (golden `portref_concat_whitespace.txt` line 9 `[f0:3:16-3:18]`), but loops backtrack to before their leading Spacing (`Input a, b [f0:1:1-1:11]`); `a [2]` binds as indexed for that reason, not because `#` is ignored.
- **Keywords are ordered-choice prefixes with no word boundary** (grammar line 13): `andx g(...)` is `and` + instance `x`. Pinned in Phase 0; fixable later by a `.peg` edit + `parser:gen`.
- **`busclose` recovery is empty** (grammar line 37; bytecode 1376–1380) → a zero-width Error at the throw cursor; `analyze.zig:164-166` widens it to one column; `ast_dump` must print the raw span.
- **Silent drops the playground will expose as "my gate vanished":** width/subscript literals parse as `u8` (`translate.zig:161`, `:289`, `:297`) and overflow drops the whole declaration via `catch {}` (`:696`); `import x ""` is kept with the literal path `"` (`:427`); `output o()` swallows the following line into the declaration (`:582`). Pinned, not fixed.
- **Empty source → `error.ParsingFailed`**, whitespace-only → `error.InvalidProgram`; `analyze.zig:142` short-circuits blank sources; the CLI's `parse failed: <errname>` (`main.zig:190-193`) is asserted by no test.
- **Columns are byte-based** (`offsetToLineCol`, `translate.zig:48-61`); the textarea counts UTF-16 — convert in the playground client.
- **Overlay keys are matched byte-for-byte** (`file_loader.zig:22`); normalise every key with `std.fs.path.resolvePosix` exactly as `resolveImportPath` joins or imports become `E009`. Today `:44` realpaths *before* the overlay lookup and `:72` realpaths unconditionally — overlay-only sibling imports fail on native, not just on wasm.
- **Freestanding compile errors are analysis-time**, not runtime: `color.zig:62` `isatty` and `builder.zig` `nanoTimestamp` fail even though unreachable (Zig 0.15.1 `std/posix.zig:44-56` freestanding stub exposes only a handful of types); `?std.fs.File.Handle` becomes `?void`; `std.debug.print` and default `std.log` route to `File.stderr()`. They surface one at a time; the Phase 2 guards are the known set, `std.json`/`std.fmt` paths may add more.
- **`lib/memory.zig`'s arena never frees**; `deinit` takes the arena by value (`std/heap/arena_allocator.zig:51`) — use `reset(.free_all)`, and only with no `Circuit`/`Session` alive.
- **`lib/log.zig` on wasm imports `onDebugLog`/`debugEnabled`**; linking `circuit.zig` into libcirc (the truth-table path) inherits them — the worker and the Node harness must supply stubs.
- **Linux Node hangs in the wasm32 runtime's `init()`** (`tests/e2e/topology_protocol_test.zig:8-20`; `pr-tests.yml:41-48`) — do not claim CI coverage for `libcirc.wasm` until root-caused.
- **The runtime follows the global `-Doptimize`** and is unstripped (933,072 B Debug; 19,628 B under ReleaseSmall — a 47× difference, almost all DWARF and name sections). `-Dwasm-optimize` must land before any size number is recorded, and the site's committed example artifacts shrink by the same factor once regenerated. `wasm-opt` is on this machine (`/usr/local/bin/wasm-opt`) but must not become a build dependency; `wasm-strip` is not installed.
- **`build.zig` links `parser.a` into 55 sites** and every consumer calls `linkLibC`; `golden_test.zig` genuinely needs libc for `setenv` (`build.zig:79-89`) — keep that one.
- **`circ-renderer` captures the theme at construction and re-instantiates per render** (`LiveCanvas.astro:104-107`); every rebuild destroys pin state unless mirrored in JS; without debounce + artifact-hash gating the Simulate tab thrashes.
- **`site/bun.lock` resolves `circ-renderer` to a github commit**; bumping requires `bun install` against the new ref.
- **PR #79 changes runtime exports, topology v03, and `setPin` settle semantics**; a libcirc built from `main` before the merge emits 0x02 — never mix a pre-merge `libcirc.wasm` with post-merge example artifacts on the site.
- **The parser is generated by a fork, not upstream langlang.** `zig build parser:gen` must invoke the fork's binary (branch `zig-parser-gen`, later a tag); a build with upstream `go/v0.0.12` on `PATH` fails with "Output language `zig` not supported". The generated file's header lines (`Runtime: … abi=N sha256=…`) are the skew signal; the runtime is complete (33 opcodes), so a grammar change never needs runtime work, but a langlang *version* bump that changes the bytecode ABI does — that lives in the fork.
- **`zig build bench` is not part of `test-all`** but CI's `bench-golden-gate.yml` hard-fails PRs whose counters drift — run it before closing any phase that touches `lib/circuit.zig` or `lib/memory.zig` (Phase 2's `memory.reset()`).
