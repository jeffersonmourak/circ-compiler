## Goal

A reader opens `/playground`, types or picks an example (any of the 10 `examples.ts` entries or the 7 tour steps, including tour step 6's two `// name.circ` blocks), and within a debounce sees: the Diagnostics tab listing `line:col CODE message` rows whose click moves the caret to the right UTF-16 column; the Preview tab showing the same `--preview --color=never` text the examples page prints; the Truth table tab rendering `--truth-table --format=json` as an HTML table (`?` for undefined cells, a message instead of a table when the circuit exceeds the 12-bit UI cap or is a stateful RAM); and the Simulate tab rendering the freshly compiled artifact through `circ-renderer`'s `renderCircuit({ bytes })`, where clicking input pins propagates, the site's light/dark toggle keeps the pins the reader set, and the canvas only rebuilds when the artifact bytes actually changed. All of it is client-side: a Web Worker owns `libcirc.wasm`, no server, no CLI. On the way there, `circ-renderer` decodes CIRF `0x03` (kinds `rom=8`/`ram=9`, ports `addr/din/we/clk`, `memory.addrWidth`), draws memory boxes with the CLI's geometry, and exports `SUPPORTED_TOPOLOGY_VERSIONS`; the site's pin moves to that revision and every example artifact is regenerated by the post-#79 compiler in the same commit, shrinking from ~921 KB to ~20 KB each. `bun run build` is green with the bumped pin, `bun test` in `site/` proves the committed `libcirc.wasm` compiles the inverter and the multi-file full adder, and every existing `<LiveCanvas>` still renders.

## Execution & Concurrency Model

This phase introduces one background context: a **dedicated Web Worker per playground page** that owns the single `libcirc.wasm` instance. The main thread never touches the instance. Ownership and guards:

- **Worker state**: `instance`, `exports`, a `TextEncoder`/`TextDecoder`. Messages are handled in arrival order by the worker's event loop; every `circ_*` call is synchronous, so two ops never interleave and the library-owned result buffer is copied out before the next message is processed. The worker calls `circ_reset` itself after every `truth_table` op (decision 5) and on `op: 'reset'`.
- **Client state** (`LibcircClient`): `pending: Map<id, {resolve, reject}>`, `nextId`. A reply with an unknown id is ignored. `dispose()` terminates the worker and rejects pending promises.
- **Component state**: a 250 ms `setTimeout` debounce on `input`; each fire bumps `gen`, splits files, and issues `analyze` then `compile` (both always — status 1 from `analyze` is the diagnostics payload; `compile` is skipped when `analyze` returned status 1). Preview runs on each fire only while its tab is active (and on tab activation); truth table likewise. Replies tagged with a stale `gen` are dropped so a slow truth table never overwrites a newer diagnostics list.
- **Simulate**: `renderCircuit` is called only when `artifact.hash` changes or the theme flips; `pins` (by name) is written from `onPinToggle` and replayed through `view.view.setInputSignal(idOf(name), sig)` after every rebuild, using the fresh topology to map names to ids (`view.runtime.topology.components`, `InputPin` with `origin.length === 0`). The `data-theme` `MutationObserver` (`LiveCanvas.astro:140-144`) and `onAssetsReady` (`:91`) trigger the same rebuild path. `renderCircuit` boots every input LOW (`runtime.ts:185-193`), so pins absent from the map are 0 by construction.
- **Lazy loading**: nothing heavy loads on page load. The worker + `libcirc.wasm` fetch start on the first `input` event or example pick; `circ-renderer` and `circ-theme.mjs` are `import()`-ed the first time the Simulate tab is opened (the `LiveCanvas.astro:41-46` memoised promises are duplicated, not shared — LiveCanvas is not on this page).

Build-time scripts (`build-libcirc.ts`, `compile-content.ts`) are synchronous `spawnSync` runs. The renderer changes are pure functions plus canvas drawing on the main thread.

## Persistence & I/O

- **Network (page)**: one `fetch` of `url('/wasm/libcirc.wasm')` inside the worker (`WebAssembly.instantiateStreaming(fetch(url), imports)` with an `arrayBuffer()` fallback for a wrong MIME type); the renderer chunk and the theme module on first Simulate. No other requests; nothing leaves the browser. `url()` (`site/src/utils/url.ts:6-9`) is applied in the Astro frontmatter, never in the worker (`import.meta.env.BASE_URL` is not relied on in worker scope).
