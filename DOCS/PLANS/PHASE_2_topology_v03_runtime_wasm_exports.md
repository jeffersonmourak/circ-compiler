## Goal

`circ-compile rom.circ -o rom.wasm` produces a self-contained v03 artifact whose `init()` materialises one engine memory node per `rom`/`ram` record, and whose host can discover a memory (`getMemInfo(id)` → `(kind<<16)|(W<<8)|A`), stage a raw little-endian image into linear memory (`memBuffer`), load it (`memLoad` → `0`, or `-2..-7` naming exactly what was wrong), mutate single words (`setMemWord`), read cells back (`getMemValue`/`getMemDefined`), export the whole memory (`memStore` → bytes written), and wipe it (`memClear`) — with the addressed word visible on `out` through the ordinary `getOutputValue` path after every mutation. `--preview` draws a `rom code[8,4]` one-input box and a `ram data[8,4]` four-input box; `--truth-table` tabulates an unloaded ROM as `?` cells and refuses a RAM with `truth-table: ram 'data' is stateful …; use --sim to drive it`; `--emit-zig` says `--emit-zig does not support rom/ram; compile to .wasm instead`; `--sim` reaches its `ready` handshake on a memory circuit (verbs arrive in Phase 3). A `mem code 2a0b…` preamble in an `expected-wasm` spec preloads a ROM in the Node harness, and `rom_lookup`/`ram_write_read` fixtures prove a lookup and a clocked write/read end to end through the real `.wasm`. v02 payloads are rejected by both readers.

pub const ComponentKind = enum(u8) { input_pin = 0, not_gate = 1, and_gate = 2, wire = 3, led = 4, output_pin = 5, slice = 6, concat = 7,

Status codes (decision 4, verbatim): `0` ok; `-1` uninitialised / bad id / not a memory; `-2` length not a word multiple; `-3` word exceeds width; `-4` too many words; `-5` `len` exceeds staging size; `-6` `memBuffer` never called; `-7` address out of range. **`-4` is never returned by `memLoad`:** the staging buffer is exactly one full image (`bpw << A`), and `TooManyWords` means `len > bpw << A == staging.len`, which `memLoad` rejects as `-5` before the codec runs. The code exists for parity with `MemoryImageError` and is reachable from Phase 3's file-backed load (`E_MEMFMT`); `DOCS/wasm-api.md` says so in the status-code table. Hosts re-view `memory.buffer` after `memBuffer` (allocation may grow linear memory). Every mutator ends in Phase 1's `memoryRefresh`, so a load that does not touch the presented address neither enqueues nor advances `current_time` (`BitVecState.equals` guard against `propagateEvent`'s short-circuit at `lib/circuit.zig:813-817`).

## Execution & Concurrency Model

This phase is fully synchronous. No background threads or workers are introduced. The runtime remains a single global `runtime_circuit` driven by host calls in program order; each export drains the event queue before returning (`propagateEvent` → `propagate`, `lib/circuit.zig:825`; `run` → `propagate`, `templates/main.zig:40`), so the queue is empty whenever a memory export invokes a Phase 1 hook — the precondition `memoryRefresh` relies on. `mem_staging` is owned by `templates/main.zig`, sized once in `init_impl`, and never freed (arena semantics, `lib/memory.zig:65-71`). The serializers, decoder, preview pipeline, and truth-table builder run in the existing single-threaded CLI path.

## Persistence & I/O

No new filesystem access in product code: memory contents cross the host boundary through linear memory (staging buffer), never files. The `.wasm` artifact gains no new sections — the v03 payloads ride in the existing `circ.topology.v0.min` / `.full` custom sections spliced by `section_writer.combineTwo` (`cmd/circ-compile/main.zig:366-371`). Tests write `combined.wasm` / `runner.js` into `std.testing.tmpDir` and spawn `node`, as today (`section_writer_fixtures_test.zig:275-286`). `DOCS/STATUS.md` gains one entry per slice.
