# Plan Prompt — Playground driver (a data view and a console over one simulation session)

## What Is Being Built

The playground's Simulate tab draws a circuit and lets a reader click pins. For a circuit whose point is a number — an 8-bit adder, an ALU, a register file — the picture is the wrong instrument: the reader wants to type `a = 0x2A`, `b = 0x13`, and read `sum` and `carry` as values, and to script a scenario the way `circ-compile --sim` lets a test runner do it (`DOCS/sim-protocol.md`: `set`, `get`, `dump`, `eval`, `reset`, and the memory verbs). Neither exists in the browser today, and there is a structural reason: `renderCircuit` creates the `CircRuntime` inside the canvas (`Playground.astro`, `buildSim`), the memory dock reaches it through `sim.view.runtime`, and the reader's pin values live in a name-keyed map the island replays onto each rebuilt canvas. There is no session a second face could drive.

This initiative gives the playground one simulation session and three faces on it. The session (`site/src/scripts/sim-session.ts`) owns the `CircRuntime` built from the compiled artifact, applies the Memory dock's ROM images as preloads, holds the root pins and memories by name in declaration order (the same collection `lib/engine_session.zig` makes: `origin.length === 0`, inputs then outputs), drives and reads through the renderer's typed runtime, and notifies its faces after every change. The **Simulate** tab becomes a face: `new CircCanvas(runtime, options)` over the session's runtime, refreshed when another face drives a pin, its clicks reported back into the session. The **Data** tab is the new second face: one row per root input with an editable value in the reader's chosen base, one row per root output with its value, `?` and per-bit unknowns spelled the way the bus dialog and the memory grid already spell them, and a reset. The **console** is the third face, in a drawer under whichever of those two tabs is open: a prompt that accepts every `--sim` verb, prints exactly the reply `--sim` would print — the handshake, `ok`, `err E_NOPIN a`, counted blocks — and keeps a history. The Memory panel moves out of the editor's dock into that drawer, beside the console, so everything that is state of the running circuit lives in one place, and the console's `load` and `save` point the reader at it rather than reaching for files themselves. The protocol parser and executor are pure modules, and the proof that the browser cannot drift from the CLI is a test that replays `tests/fixtures/sim/*.script` through the executor over artifacts compiled by the committed `libcirc.wasm` and compares the transcript byte for byte with `tests/fixtures/expected-sim/*.txt`.

The compiler does not change. `--sim` stays out of `libcirc` (a playground decision: the worker has no session protocol), so the browser runs the artifact's own runtime, which is what `--sim` maps its verbs onto one to one. The renderer does not change either: everything the session needs is exported already (`CircRuntime`, `CircCanvas`, `parsePinValue`, `formatPinValue`, `widthMask`). **Definition of done:** on `/playground`, with `four-bit-adder` loaded, the Data tab shows `a`, `b`, `cin` editable and `sum`, `cout` read, typing `0xA` into `a` updates `sum` and the canvas on the Simulate tab together; the console under either tab accepts `eval a=0xA b=0x5 => sum cout` and prints `ok sum=0xf/0xf cout=0x0/0x1`; `set clk 0` then `set clk 1` on `ram-write-read` writes the RAM and the drawer's Memory tab shows it; the four sim transcripts replay byte for byte under `bun test`; `bun test`, `bun --bun run typecheck`, `bun --bun run build` and `bun run bundle` are green with no ceiling raised; `zig build test-all` is untouched; `DOCS/sim-protocol.md` gains a section on the browser console and `DOCS/decisions/playground.md` the decisions each phase exercised; the human has reviewed each phase on the page.

## Architectural Constraints

- **One session, three faces.** The island owns exactly one `SimSession` per compiled artifact. Every drive — a click on the canvas, an edit in the Data tab, a console verb — goes through the session, and every face reads from it. No face holds a `CircRuntime` of its own, and no face writes the runtime around the session.
- **The console cannot drift from `--sim`.** The parser (`sim-protocol.ts`) and the executor (`sim-executor.ts`) are pure modules whose replies are the protocol's text, and `site/test/sim-transcripts.test.ts` replays every `tests/fixtures/sim/*.script` through them over artifacts compiled by the committed `libcirc.wasm`, comparing to `tests/fixtures/expected-sim/*.txt` byte for byte. A verb the browser cannot honour as the CLI does is a recorded difference in `DOCS/sim-protocol.md`, never a silent one; a transcript line that differs is a failing test.
- **The compiler and the worker do not change.** `--sim` stays out of `libcirc` (`DOCS/decisions/playground.md`, "A live editor ships inert and shares one worker", and the playground plan's anchor). The browser drives the artifact's runtime, which `--sim`'s verbs map onto one to one (`DOCS/sim-protocol.md`, "Each command maps 1:1 onto the artifact's WASM exports").
- **The renderer does not change.** Everything needed is exported at the pinned sha; a renderer slice would be a pin bump and the human's push, and none is planned. `CircCanvas` keeps its own `inputState` for `getInputValue`; the island never reads it (it keeps pins by name), so a drive that bypasses the canvas leaves nothing the island relies on stale.
- **Values are spelled one way across the site.** The Data tab reads and writes through the renderer's `parsePinValue`/`formatPinValue` in `settings.valueFormat`, the spelling the bus dialog and the memory grid use (`?` unknown, `x` per unknown bit, `0x`/`0b` prefixes override the base). The console spells values the protocol's way (`parseValue`, lowercase `0x` hex out) because its output is `--sim`'s transcript, and a reader pastes it into a test.
- **The JavaScript budget is per page and gzip is the gate** (`DOCS/decisions/playground.md`). The session, protocol, console and data modules load through the same dynamic `import()` chain as the renderer (from `buildSim`), so they stay out of `/playground`'s eager graph; the lazy chunk is measured in STATUS every phase.
- **ROM images are session state and the preloads of the session** (the decision of that name). The session applies `settings.romImages` at build and at `reset`, exactly as `--sim` applies `--mem` preloads (`lib/sim/loop.zig`, `applyPreloads` after `Session.build`); a console `poke`/`clear` is mid-session state the next `reset` drops, as the protocol says. Files come and go through the Memory tab only.
- **Two debounces, a sequence counter per stage** stays as it is; the session is built from the artifact hook (`hooks.onArtifact`) and replaced on a new artifact, never rebuilt on a keystroke.
- **The envelope changes by values, not a version.** `OutputTab` gains `'data'`; `DockTab` loses `'memory'` (the panel moves to the drawer); the drawer's height is one more key in `layout.ratios`, the record that was written so a second divider costs no schema change; `normalize` already falls back an unknown tab, so an older envelope needs no migration. Console history and transcript are session state, never persisted.
- **Git conduct per `CLAUDE.md`:** stage by path, Conventional Commits under 70 characters (scope `site`), no phase or slice prefixes, no trailers, never push.

**Locked decisions.** Routine calls made at plan time so no slice reopens them. Each phase appends the ones it exercises to `DOCS/decisions/playground.md`.

1. **The session is a class over an injected runtime, and it owns the runtime's life.** `SimSession` is constructed from `{ bytes, roms, images, warnings, load }` where `load` is `CircRuntime.loadFromBytes` in the page and any `RuntimeLike` factory in a test. It exposes `pins` (`PinRef { name, id, width, kind: 'in' | 'out' }[]`, inputs then outputs in declaration order, `origin.length === 0` only), `mems` (`MemRef { name, id, width, addrWidth, kind }[]`, root only), `set(name, value, defined)`, `get(name)`, `dump(which)`, `eval(assigns, queries)`, `reset()` (a new runtime from the same bytes, preloads re-applied, pins dropped), the memory verbs, `subscribe(listener)` and `destroy()`. Every mutator settles (`setValueAndRun`) and then notifies. The canvas's `onPinChange` is wired into the session so a click notifies the other faces too.
2. **Errors are the protocol's, as values.** Session methods return `{ ok: true, ... } | { ok: false, code: SimError, arg?: string }` with `SimError` the ten codes of `lib/sim/protocol.zig` (`E_PROTO`, `E_NOPIN`, `E_NOTIN`, `E_WIDTH`, `E_BADVAL`, `E_NOSETTLE`, `E_NOMEM`, `E_IO`, `E_MEMFMT`, `E_ADDR`). The executor formats them as `err <CODE> <arg>`; the Data tab formats them as a sentence. One set of reasons, two spellings.
3. **`reset` rebuilds the canvas; a new artifact replays the pins.** The protocol's `reset` leaves every pin undefined and re-applies preloads; the session emits `rebuilt` and the island builds a fresh `CircCanvas` over the new runtime without replaying `sim.pins`. A new artifact (a successful compile) builds a fresh session and *does* replay the reader's pins by name, as today. `quit` in the browser prints `ok bye` and is otherwise `reset`: there is no process to end.
4. **Files are the Memory tab's; the console points at it.** The executor's `load <mem> <path>` and `save <mem> <path>` go through an injected `FileSource { read(path); write(path, bytes) }`. In the transcript test it is the repository's `tests/fixtures/mem/` directory, so `err E_IO tests/fixtures/mem/does_not_exist.bin: FileNotFound` and `err E_MEMFMT …: 17 words exceed capacity 16` replay exactly. On the page it is a source that refuses every read and write with one reason, so the reply stays protocol-shaped: `err E_IO <path>: load images in the Memory tab` and `err E_IO <path>: save images from the Memory tab`. The Memory tab already reads an image file (`imageFromBytes`); it gains a save button over the session's `storeImage`. `E_MEMFMT` reasons are the compiler's wording (`lib/engine_session.zig`'s `writeImageError`), which differs from `rom-image.ts`'s `describeRomError` (dock sentences); the executor gets its own byte-level validator and reasons in Phase 2.
5. **The handshake is printed when the session is built, and `pins` re-prints it.** `ready proto=1 pins=<N> warnings=<W>`, one `pin <name> <in|out> <width>` per root pin, one `diag warning <CODE> <file>:<line>:<col> <message>` per warning from the current analysis, with `<file>` the tab's file name. A session built with errors never happens (the artifact hook fires only on a good build), so `error diags=…` is never printed.
6. **The drawer is one element under two tabs, with two tabs of its own.** A single `.pg-drawer` region lives once in the output pane below the panels, `hidden` unless `state.tab` is `simulate` or `data`, and holds a tab strip — **Console** and **Memory** — over one body. The Console tab is a scrollback `<pre>` (`aria-live="polite"` on replies), a one-line `<input>` prompt, ↑/↓ history of 100 lines, `Ctrl+L` clear; one history and one transcript whichever output tab is open, because it drives one session. The Memory tab is today's memory panel, moved. The drawer's height is a second splitter (`layout.ratios.drawer`), collapsible to its strip; which drawer tab is selected is an island field, session-only.
7. **The Data tab is rows, and an edit is a session drive.** `data-view.ts` is pure: `rowsFor(session, format)` → `{ name, width, kind, text }[]`; `editRow(session, name, text, format)` parses through `parsePinValue` and drives through `session.set`, returning the protocol error or `ok`. A width-1 input is a toggle button as well as a field; a bus input is a field that commits on Enter or blur; an output is text. Rows re-render on every session notification. The tab shows `Compile a circuit first.` and `Fix the errors to simulate.` under the same rules as Simulate.
8. **The Memory panel reads the session and lives in the drawer.** In Phase 0 `memHost()` returns the session's runtime, so the panel's grid, its image loading and its RAM view work whenever a session exists, whichever of Simulate or Data is open, and `applyToView` becomes the session's preload step. In Phase 3 the panel moves from the editor dock to the drawer's Memory tab, shown only while the circuit declares a memory, as its dock tab was; `DockTab` becomes `'diagnostics' | 'settings'`, and the dock's memory-deferred bookkeeping goes with the tab.
9. **A session lives as long as its artifact.** It is built lazily the first time Simulate or Data is opened with an artifact (as `buildSim` is today) and destroyed with its runtime when the artifact is replaced or cleared. The Simulate canvas is built over it on demand and destroyed without destroying the runtime.
10. **The transcript test compiles its circuits in the test.** `site/test/sim-transcripts.test.ts` reads `tests/fixtures/circuits/<root>.circ` (and its imports through `requestFor`), compiles through `instantiateLibcirc`/`callOp('compile')` as `libcirc.test.ts` does, loads the bytes into a real `CircRuntime`, builds a `SimSession` with the fixture's preloads through the fixture `FileSource`, feeds every script line to the executor, and compares the joined output to the golden. It honours `SKIP_LIBCIRC_TEST=1`. The four fixtures and their expectations are read from the repository, not vendored, so they cannot drift from the CLI's own golden test.
11. **The console's value spelling is the protocol's; the Data tab's is the site's.** `sim-protocol.ts`'s `parseValue` mirrors `std.fmt.parseInt(u64, text, 0)` over `bigint` (prefixes `0x`, `0o`, `0b`, underscores allowed anywhere between digits, decimal default, no sign, at most 64 bits); replies write lowercase `0x` hex as `writeHex` does. The Data tab uses `parsePinValue`/`formatPinValue` in `settings.valueFormat`, and a change to the setting re-renders it as it re-formats the canvas.
12. **Documentation lands with the code.** `DOCS/sim-protocol.md` gains "The protocol in the browser" (`load`/`save` as the Memory tab's, `quit`, preloads from the Memory tab, the handshake's file name) in Phase 3; `DOCS/decisions/playground.md` gets one `###` per exercised decision per phase; the archive is produced per `DOCS/prompts/ARCHIVE.md` when the human asks.

Phases are ordered by dependency, not by priority. Each phase must be fully shippable before the next begins.

**Explicitly deferred, and not to be smuggled into a slice:** `--sim` in `libcirc` or the worker; any renderer change; a clock or step-by-step propagation view (the protocol has no clock; `set` settles); persisting console history or transcripts; files through the console (a drop box, a picker, a download from `save`); scripting beyond the protocol (loops, variables, assertions); a waveform or history of values; timing or the event queue; `E_NOSETTLE` (the CLI never emits it); running the console against the ASCII preview or the truth table.

**Sequencing notes for the execution agent.** Phase 0 goes first because both features are faces on a session that does not exist, and it must be invisible: the page behaves as before or the rewiring is wrong. Phase 1 precedes the protocol because the Data tab exercises the session's drive and notify paths from a second face with no parser in the way, which is where a session bug shows first. Phase 2 is pure modules and a parity test, and lands before any console UI so the UI has a proven executor to call. Phase 3 is the drawer — the Memory panel's move, the console — and the one document section. Phase 4 is the review of the whole.

**Slice seams handed to the deep planner.** `DOCS/prompts/PHASE_DEEP_PLANNER.md` owns each phase's `## Slices` table; once `DOCS/PLANS/PHASE_<N>_<name>.md` exists its table is authoritative. Two phases have pre-agreed seams:

## Working Loop

The execution agent follows this loop every session without exception:

### On Cold Start

1. Read this file (`DOCS/PLANS_PROMPT.md`) in full.
2. Read `DOCS/STATUS.md` (if it exists). The latest entry defines what was last shipped and what comes next.
3. Run `git log --oneline -10` and `git status`. If STATUS claims a slice is committed but it does not appear in `git log`, the human has not committed yet — **do not begin a new slice**. Stop and say so.
4. Read the active phase plan (`DOCS/PLANS/PHASE_<N>_<name>.md`) for the current phase.
5. Implement the next slice per the phase plan. Do not start a second slice until the first is reviewed and committed.

### Each Slice

1. Implement the full slice as specified. Do not stop mid-slice.
2. Run the gates for what the slice touched: `bun test`, `bun --bun run typecheck`, `bun --bun run build`, `bun run bundle` in `site/`. Do not ship a slice that breaks a suite.
3. Append a STATUS entry (template below).
4. Stage the slice's files (`git add <files>`), by path.
5. Display the proposed commit message and **stop**. Wait for explicit human approval before running `git commit`. Do not begin the next slice until the commit is confirmed and made.

### Git Rules

- Read-only git commands (`status`, `log`, `diff`) are encouraged for situational awareness.
- **Committing:** At the end of a slice — and only at the end of a slice — the agent stages the slice's files (`git add <files>`), then displays the full proposed commit message to the human and waits for explicit approval before running `git commit`. Staging first lets the human inspect the diff in any git client before approving. Do not commit without that confirmation.
- Do **not** push, force-push, amend, rebase, reset, delete branches, or run any other write `git` or `gh` command under any circumstances.

## Recurring Traps

Add an entry here during execution whenever a non-obvious constraint surfaces — in the same slice that hit it, under the group it belongs to — and name it in that slice's STATUS entry `Notes:` line.

**The runtime**

- `CircRuntime.readValue(id)` reads any component through `getOutputValue`; for a root input pin that is the value it was driven to, which is what `get <input>` returns in `--sim` (`readPin` in `lib/sim/loop.zig`). `setValue` on a non-input id is a silent no-op in the artifact (`DOCS/wasm-api.md`), so the session must refuse `E_NOTIN`/`E_NOPIN` itself, before the call.
- `loadMemImage(id, bytes)` returns the runtime's status (`-2` not a whole number of words, `-3` a bit at or above the width, `-5` over the staging buffer; `-4` cannot occur through it); the protocol's `E_MEMFMT` reasons come from validating *before* the call, as `--sim` does (`validateImage`), so the wording is the compiler's, not a status number.
- The artifact has no `reset` export (`DOCS/decisions/runtime-api.md`); `reset` is a new instantiation from the same bytes. The old runtime must be `destroy()`ed, and any `CircCanvas` over it destroyed first.

**The island**

- `hooks.onArtifact(bytes, reason)` fires with `null` on a failing build and on a file-set change; the session must survive `null` (destroyed, faces blank with the same sentences Simulate shows today) and a later `bytes` (a fresh session, pins replayed by name).
- `state.simulateEnabled` is false when the renderer and the compiler disagree on the topology version; the Data tab and the console follow the same flag, since all three faces need a runtime the renderer can decode.
- The truth-table pre-flight and the `stateful ram` refusal (`lib/libcirc/modes.zig`) are the truth table's; a `ram` is exactly what the console and the Data tab are for.

**Tests**

- `bun test` has no worker: a test that needs a compiled artifact instantiates `libcirc.wasm` directly through `libcirc-abi.ts` (`instantiateLibcirc`, `callOp`), as `libcirc.test.ts` does, and honours `SKIP_LIBCIRC_TEST=1`.
- `island-smoke.test.ts` asserts the output strip is exactly `['preview', 'truth', 'simulate']` (line 245); Phase 1 changes that assertion with the tab.
- The transcript goldens are `tests/fixtures/expected-sim/*.txt` in this repository, regenerated only by `UPDATE_GOLDENS=1 zig build test`; the site test reads them and never writes them.
