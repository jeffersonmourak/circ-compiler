# Plan Prompt — Playground v2 (a workbench, not a demo)

## What Is Being Built

`/playground` today is a `<textarea>`, an example `<select>`, and four tabs (`site/src/components/Playground.astro`, 460 lines, no framework). It proves the compiler runs in the browser and nothing more: no highlighting, no squiggles, no file tabs, no panes, no memory of what you typed, no way to send anyone what you wrote. This initiative turns it into the place a reader actually writes circ, and turns every tour step and example into a door into it. The stack does not change — Astro 5 islands, TypeScript, bun, one `libcirc.wasm` in a Web Worker, `circ-renderer` pinned by sha. What changes is everything between the reader's fingers and those parts.

The work is designed from two journeys. **The visitor**: reads a tour step, edits the live editor embedded under it, clicks *expand* and lands in the full playground with their edit intact, sees a syntax-highlighted editor with red squiggles under the exact token the compiler complained about, drags the split so the schematic gets more room, adds a second file as a tab, hovers an AND box in the simulation and watches its declaration light up in the editor, loads a ROM image and reads it back out of the truth table, reloads the page and finds their work, copies a URL that reproduces it byte for byte. **The maintainer**: adds one entry to `site/src/content/examples.ts`, runs `bun run scripts/compile-content.ts`, and the example shows up in the playground's workspace with an "Open in playground" button on the gallery page without touching the playground code; bumps the `circ-renderer` pin with one `bun add` and one commit, and `site/test/renderer-pin.test.ts` proves the committed module and the new decoder still agree.

Definition of done, all of it observable in a browser: a visitor opens `/playground` and gets a syntax-highlighted circ editor with diagnostics as squiggles and gutter markers; edits a multi-file project as tabs over the existing `// <name>.circ` marker format; sees Diagnostics / Preview / Truth table / Simulate update live behind a Live / Compiling / Error status that also names the compiler version, revision and artifact size; hovers a component on the simulation canvas or a truth-table column header and sees its declaration highlighted in the editor, and vice versa from the cursor; resizes panes by dragging or by arrow keys; reloads and finds their scratch work; shares a URL that reproduces the exact source; opens any tour step or example in the playground with one click; loads a ROM image into a declared `rom` and sees it in both the truth table and the simulation; and tour pages embed small live editors that lazy-load and expand into the real playground. `bun test` and `bun --bun run build` stay green after every slice, and a new per-page JavaScript budget gate stays green too. The single hard prerequisite that is not UI work is fixed first: `circ_compile`'s import-free fast path does not resolve implicit builtin macros, so tour step 5's own prose ("In a single-file program you import macros explicitly", `site/src/content/tour.ts:98`) invites the reader to delete the `import xor "<builtin>/xor.circ"` line at `tour.ts:101` and get `E001: undeclared name 'xor'` from a circuit that previews and tabulates fine. That lands in Phase 0, in Zig, with every committed artifact regenerated from the same revision.

## Architectural Constraints

- **No React, no Monaco.** The editor is CodeMirror 6, loaded on the playground and live-editor islands only, never in the base bundle of `/`, `/reference/*`, or `/download`. Any dependency beyond the CodeMirror packages named above must be justified in its slice's STATUS entry.
- **The single-string source with `// <name>.circ` markers is the interchange format** and does not fork. `site/src/utils/split-files.ts` (`MARKER = /^\/\/\s+([\w_.-]+\.circ)\s*$/` at `:14`, `splitFiles` `:16`, `rootOf` `:34`, `PLAYGROUND_DIR = '/playground'` `:37`, `requestFor` `:40`) stays the only reader; it is shared with `site/scripts/compile-content.ts:59-62`. Tabs, localStorage, and share links are all views over that one string.
- **The Web Worker owns the wasm instance** (`DOCS/decisions/libcirc.md`, "Playground artifacts are committed; the module runs in a Web Worker"). Nothing on the main thread instantiates `libcirc.wasm`.
- **`--sim`, `--emit-zig`, `--inspect` are not exported through libcirc** (`DOCS/decisions/libcirc.md`, "Not exported through libcirc"). Prefer analysis-driven joins (`analyze.symbols` / `analyze.references` by name) over new library exports. A new export would need its own slice with C ABI + wasm + tests + `DOCS/libcirc-api.md`; no phase in this plan requires one.
- **One revision for the compiler and every site artifact** (`DOCS/decisions/libcirc.md`, "The renderer follows the compiler, once, per topology version"). If a slice changes Zig, that same slice runs `zig build circ-compile`, `bun run libcirc` and `bun run scripts/compile-content.ts` and commits the regenerated `libcirc.wasm`, `libcirc.manifest.json` and the 11 `site/public/wasm/*.wasm`.
- **The renderer follows the compiler, once, per topology version** — the heading of that name in the same file. Any `circ-renderer` change lands on branch `host-pin-api` in `/Users/jeffersonmourak/circus/circ-renderer`, is pushed to GitHub (the `github:` specifier resolves from the remote, never from a local path), and is consumed by `bun add circ-renderer@github:jeffersonmourak/circ-renderer#<newsha>` — which rewrites `site/package.json:17` and both `site/bun.lock` entries. `site/src/utils/renderer-versions.ts` re-exports `SUPPORTED_TOPOLOGY_VERSIONS` from the package so the pin and the site's list cannot drift; `site/test/renderer-pin.test.ts` is the gate.
- **Zig changes follow `CLAUDE.md`:** diagnostic codes are append-only, `tests/fixtures/expected-*` stay byte-stable unless the slice says why, `zig build test-all` green.
- **Accessibility and theme.** Every interactive control is keyboard-operable — tabs (roving tabindex), splitters (`role="separator"`, `aria-orientation`, arrow / Home / End), the workspace list, the settings drawer (`<label for>` on every control, the pattern `Playground.astro:28-29` already uses). Light and dark follow `document.documentElement.dataset.theme` (`site/src/components/ThemeToggle.astro:9-16` sets it and writes `localStorage.theme` at `:14`; `site/src/layouts/Base.astro:63-73` pre-paints it). **`ThemeToggle.astro` dispatches no event** — observe the attribute with a `MutationObserver`, as `Playground.astro:452-455` already does. No page-level horizontal scroll at any width.
- **Nothing heavy loads before interaction.** `libcirc.wasm`, `circ-renderer` and `site/src/utils/circ-theme.mjs` stay behind dynamic `import()` / first-focus, the pattern `LiveCanvas.astro:41-46` and `Playground.astro:347-348,458` already use.
- **Git conduct** per `CLAUDE.md`: stage by path (`git add <files>` — never `-A`, never `.`, never `commit -a`, rule at `CLAUDE.md:185`), Conventional Commits titles under 70 characters (`:190`), **no phase or slice prefixes** (`:206`), **no trailers of any kind** (`:184`), never push.

**Locked decisions.** These are the routine calls made at plan time so no slice has to reopen them. Each phase appends the ones it exercises to a new `DOCS/decisions/playground.md`, which the slice that creates it also registers under "Topics" in `DOCS/decisions/index.md` alongside the seven existing topic files, following that file's stated convention (`###` headings inside topic files, referenced by heading slug, never by number).

1. **Editor: CodeMirror 6, hand-picked packages, `StreamLanguage` grammar.** Depend on `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/commands`, `@codemirror/lint`, `@lezer/highlight` — not the `codemirror` meta-package (it drags in autocomplete, search and lint unconditionally). The circ mode is a `StreamLanguage` over a hand-written tokenizer, not a Lezer grammar (a Lezer grammar needs `@lezer/generator` as a build step and a generated file to keep in sync; circ's token set is a dozen regexes). No autocomplete provider in this initiative. **No CodeMirror code exists in this tree and `site/node_modules` is not installed**, so no CodeMirror API named anywhere in this plan has been verified — treat every CM6 name here as intent, not as a verified API. Phase 1's first slice is a spike that installs the packages, pins exact versions in `site/package.json`, **reads the installed `.d.ts` files before writing a line against them**, stands up a two-line editor, and records in STATUS the exact extension names it used. 5. **Name join, not span join.** Outputs carry no source spans, so editor↔output linking joins on the declared name: `analyze.symbols[].{name, kind, file_id, range}` (already emitted — example at `DOCS/analyze-api.md:49-50`, contract at `:57`; `lib/analyze/analyze.zig`) against `FullComponent.name` / `PlacedComponent.name`, restricted to top-level components (`origin.length === 0`, the rule `Playground.astro:354` already uses). **`Playground.astro:77-81`'s `Analysis` interface drops `symbols[].range` and omits `references` entirely** — Phase 1 widens it. Preview-pane hover stays deferred: `circ_preview` returns text with no spans and no cheap exact mapping exists.
6. **Share encoding: `#src=` deflate-raw + base64url, `#src0=` plain fallback, 8 KB cap, fragment scrubbed on load.** `#src=<base64url(deflate-raw(UTF-8 source))>` via `CompressionStream('deflate-raw')` / `DecompressionStream('deflate-raw')`; where those are absent, `#src0=<base64url(UTF-8 source)>`. Two distinct keys instead of a version byte. If the encoded payload exceeds **8192 characters** the Share button refuses and offers "copy the source" instead. A hash wins over the persisted active project on load; the loaded source becomes a new scratch project named with the existing `generateSillyName()` (`site/src/utils/sillyname.ts:23`). **An incoming `#src=` is decoded on load and then removed with `history.replaceState`**, so the visitor's source does not linger in a URL that analytics could capture — `site/src/pages/playground.astro:13-19` promises "nothing leaves the page" and `Base.astro:62` mounts `<PostHog />` on every page. `TODO(phase4)` in Open items carries the spike. Encoder and decoder are pure functions in a new `site/src/utils/share-link.ts`, round-trip tested under `bun test` over every example and tour source. **Content deep links use a separate key that carries no source.** `/playground#pick=example:<slug>` and `/playground#pick=tour:<n>` name content the page already ships (`Playground.astro:66`'s `#pg-picks` blob, and the same id shape decision 7 stores), so the buttons on `/examples` and `/tour` never encode source text and never touch the 8 KB cap. Load precedence, highest first: `#src=` / `#src0=`, then `#pick=`, then the persisted `activeId`, then `picks[0]`. All three keys are consumed and then removed with `history.replaceState`. An unknown key, an unknown id, or a payload that fails to decode falls through to the next rule and writes a status-bar note; it never throws and never leaves a blank editor.
7. **Persistence: one key, one envelope, schema-versioned, quota-safe.** `localStorage['circ.playground.v1']` holds `{ version: 1, scratch: [{ id, name, source, updatedAt }], activeId, activeFile, layout: { ratios }, settings: { … }, tab }` — split ratios and settings ride in the same envelope so a schema reset is one `removeItem`. Limits: **at most 16 scratch projects, at most 32 KB per source, at most 256 KB per envelope.** Writes are debounced 500 ms; every read and write is wrapped in `try/catch`; a `version` mismatch resets to defaults with a status-bar note (no migration path before v2); `QuotaExceededError` evicts the least-recently-updated scratch project and retries **once**, then disables persistence for the session and says so — **and that eviction path must be exercised by a test, not assumed.** **Never persist example or tour text — store ids** (`example:<slug>` / `tour:<n>`, the shape `Playground.astro:66`'s `#pg-picks` blob already uses); copies go stale the moment `examples.ts` changes. langlang's corruption heuristic `JSON.stringify(ws).includes("undefined")` (`workspace/useWorkspacePlayground.ts:88`) is explicitly **not** copied — it false-positives on any source containing that word. The tree ops live in a framework-free `site/src/utils/playground-store.ts` and are tested as pure functions. **Flat projects only** — no folders, no directory nodes. **`site/src/utils/playground-store.ts` and the `circ.playground.v1` envelope are created in Phase 3, slice 3** — the first slice that persists anything (`layout.ratios`). Phase 3 writes the whole envelope shape (`scratch`, `activeId`, `activeFile`, `settings`, `tab` present but empty and unread) plus `read()`/`write()`, the 500 ms debounce, the try/catch, the version-mismatch reset and the eviction path with its `bun test` case. Phase 4 fills `scratch`/`activeId`/`activeFile`; Phase 6 fills `settings`; neither adds a second key nor bumps `version`.

9. **Two debounces, sequence numbers on both stages.** `ANALYZE_DEBOUNCE_MS = 120` drives `analyze` (squiggles, symbols, references); `BUILD_DEBOUNCE_MS = 350` drives `compile` and, if its tab is active, `preview` / `truth_table` (today there is one `DEBOUNCE_MS = 250` at `Playground.astro:85`). Each stage carries its own monotonic sequence counter and drops results whose sequence is stale — **including the second stage**, which is the bug in the langlang playground the site must not copy (`PlaygroundPage.tsx:252-258` guards the compile stage and leaves the match stage unguarded). Dropping a stale reply is **not** cancellation: `LibcircClient` has no abort and no timeout, and the wasm keeps computing — see the trap. On status 1 the diagnostics render and the **last good preview / table / canvas stay on screen**, dimmed, with the status dot in Error; they are cleared only when the source's file set changes.
10. **Layout: an `app` variant on the existing `Base.astro`, not a second layout.** `Base.astro` gains `layout?: 'default' | 'app'` (default `'default'`, so no other page changes) which stamps `data-layout="app"` on `<body>` (`Base.astro:75`); CSS then makes the body a `100dvh` grid of `auto 1fr auto` with `overflow: hidden` and drops `main`'s `max-width: 1100px` / `padding` (`site/src/styles/global.css:86-90`). Splitter ratios are CSS custom properties on the pane container, so a drag writes one property and never re-lays-out the editor.

**Pillar 4(a) — the builtin fast path**

- **`circ_preview` and `circ_truth_table` always take the project route; `circ_compile` does not** (until Phase 0) — `cmd/circ-compile/main.zig:253-261`. That asymmetry is why a circuit can preview and tabulate perfectly while `compile` returns `E001: undeclared name 'xor'` — and why the Simulate tab, alone, goes empty (`DOCS/archive/plan-libcirc.md:191`).
- **Committing a Zig change means committing three sets of artifacts** in the same slice: `site/public/wasm/libcirc.wasm` + `libcirc.manifest.json` (`bun run libcirc`) and the 11 committed `.wasm` files — 10 example slugs + `hero-half-adder.wasm` — (`bun run scripts/compile-content.ts` after `zig build circ-compile`, which the script expects at `zig-out/bin/circ-compile`, `compile-content.ts:40`). **The same run also writes 7 untracked `tour-<N>.wasm` files** (`compile-content.ts:93-99`) that have never been committed and that `site/.gitignore` does not cover: expect them in `git status`, and never stage them. `site/test/libcirc.test.ts:30-39` and `site/test/renderer-pin.test.ts:17` are the gates that catch a half-done regeneration.
- **The committed manifest's `revision` names the commit before the one that commits it.** Inherent to committing a build product; the example artifacts already behave that way.

**Pillar 4(b) — status 1 and recovered syntax**

- **The library and the CLI disagree on recovered syntax errors:** `libcirc.compile`/`preview`/`truthTable` return status 1 with `syntax` diagnostics for a file whose declaration was dropped by parser recovery, while `circ-compile` still compiles it (`DOCS/archive/plan-libcirc.md:192`). Pre-existing, deliberately unchanged; the UI must show the diagnostics and keep the last good outputs on screen, dimmed.
- **Parser quirks the playground will surface as "my gate vanished":** a width or subscript literal above 255 drops the whole declaration and still reports `Errors (0)`; `import x ""` is kept with the literal path `"`; `output o()` swallows the following line; `andx g(...)` splits into `and` plus an instance `x`, because keywords have no word boundary. All pinned by goldens under `tests/fixtures/expected-ast/recovery_*.txt`, none fixed here — a playground invites exactly this free typing.

**Pillar 4(c) — columns and lines**

- **Analyze columns are 1-based byte offsets** (`DOCS/analyze-api.md:66-70`); an editor counts UTF-16 code units. Convert at the boundary with `byteColToUtf16` (`site/src/utils/columns.ts:6-17`) — CodeMirror wants absolute document offsets, so line-start plus the converted column, the job `caretOffset` (`columns.ts:20-26`) does today.
- **A diagnostic's line is file-local; the combined document's line is not.** `SplitFile.startLine` is the 0-based offset of a file's first body line in the combined text (`split-files.ts:10-11`), and `locate()` (`Playground.astro:281-289`) is the existing mapper. Tabs change nothing about this: the request still carries per-file bodies.
- **`<builtin>/…` paths appear in `analyze.files`** and have no editor buffer (`DOCS/analyze-api.md:55`). Skip them when mapping `file_id` to a tab — and expect far more of them after Phase 0, since implicit builtins will now be resolved on the compile route too.

**Pillar 4(d) — staleness, and the absence of cancellation**

- **`circ_result_ptr()` is valid only until the next `circ_*` call** (`DOCS/libcirc-api.md:160`). The worker is one instance handling messages serially, which also means **there is no real cancellation**: `LibcircClient` has no abort and no timeout (verified — no such token exists in `site/src/scripts/libcirc-client.ts`). "Cancelling" is dropping a reply by sequence number while the wasm keeps computing. A 4,096-row truth table cannot be stopped, so the pre-flight cap in decision 13 is the only real defence.
- **`compile` transfers `bytes.buffer`** (`libcirc.worker.ts:63-65`). The artifact arrives as a transferred `Uint8Array`; keep exactly one reference. Passing it to a second consumer that transfers again detaches it, and the canvas then throws on a detached buffer. Phase 5 and Phase 7 both add second consumers.
- **Artifact identity is the FNV-1a hash** of the bytes (`Playground.astro:319-326`, compared at `:198` and `:433`). Any new consumer must hash the same way or it will rebuild the canvas on every keystroke.
- **A reply can outlive the document it was computed against.** `state.gen` only moves on the *next* debounced run, so an in-flight analyze or compile can land after the reader has typed on. `fire()` captures `const snapshot = state.source` and maps offsets against that; `editor.setDiagnostics` is skipped whenever `snapshot !== state.source`, because `@codemirror/lint` maps registered diagnostics forward through later changes and cannot know they were stale to begin with. The diagnostics *list* still renders — it carries file-local positions, which do not go stale the same way.
- **`truth_table` is followed by `circ_reset()`** (`libcirc.worker.ts:62`) — the engine arena is released immediately, so nothing carries over between truth-table calls.
