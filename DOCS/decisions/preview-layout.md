# preview-layout

The entries below record the decisions of the layout-rewrite initiative: the ASCII `--preview` layout in `lib/preview/layout/` and its TypeScript port in `circ-renderer/src/layout/` are rebuilt as a layered-graph layout with channel routing, and must produce the same `LayoutGrid`. The fifteen decisions locked at plan time are in the layout plan prompt, archived at `DOCS/archive/plan-layout.md` and readable in full at `git show 06d115ec5378e07100fd80afa075d5e72cc076d1:DOCS/PLANS_PROMPT.md`; each phase appended the ones it exercised here as it shipped them. The render conventions the layout feeds are in `DOCS/preview.md`.

### The parity contract is a JSON projection, not either side's native type

**Decision.** `lib/preview/dump_json.zig` emits a `LayoutGrid` as JSON with camelCase keys over the common field set of both grids — `width`, `height`, `components[] { id, kind, name, x, y, width, height, inPorts[] { portName, coord }, outPort, bitWidth }`, `wires[] { srcId, srcPort, dstId, dstPort, segments[] { from, to } }` — and nothing else. `kind` is `{ tag: "primitive", kind: <u8> }` in the wire-format numbering (`lib/topology/format.zig`, mirrored by the TS `ComponentKind` enum) or `{ tag: "subcircuit", subcircuit }`. Formatting is fixed (two-space indent, one component or wire per line) so a golden diffs per component and per wire. `tests/preview/layout_conformance_test.zig` pins one file per previewable fixture-mode under `tests/fixtures/preview/layouts-json/`; `circ-renderer/test/layout-parity.test.ts` projects `buildLayout()` onto the same shape and compares vendored copies. Zig's types are untouched.

**Rationale.** The two grids are not the same type and should not be forced to be: `origin` and `display_label` are render-only, `slice` / `memory` aux and `realSrcId` exist only in TS, and `crossings` is derived data the two sides have classified differently. Comparing the projection compares what a reader sees — box geometry and wire paths — and identical segments imply identical crossings once both sides derive them the same way (Phase 3, decision 11). Hand-emitting avoids `std.json`'s snake_case struct output and keeps the file diffable.

**Alternatives.** Comparing the existing text dump (`dump.zig`; not parseable from TS without a second parser); adding TS-only fields to the Zig structs; asserting parity in Zig by re-implementing the TS router (the drift the contract exists to catch). This entry is carried over unchanged from the discarded incremental attempt (`layout-v1-attempt`), whose contract it was.

### The corpus invariants are the measurement of record

**Decision.** `lib/preview/layout/invariants.zig` counts, over a `LayoutGrid` and without rendering, four invariants and four measurements: I0 wire cells inside a component body, I1 cells two or more nets cover with the same orientation, I2 cells where two or more nets meet other than as a clean perpendicular pass-through, I3 nets whose cells are not one 4-connected set from their source cell (or whose wires have a broken or non-axis-aligned segment chain), plus crossings, bends, straight wires and the wire count. A *net* is `(src_id, src_port)`; a net may share cells with itself freely. `tests/preview/layout_conformance_test.zig` writes one line per previewable fixture-mode — every one, zero rows included — and a totals line into `tests/fixtures/preview/layout-invariants.golden`, and the corpus JSON goldens beside it; both are regenerated with `UPDATE_GOLDENS=1 zig build test` and reviewed like any other golden. Until Phase 3 lands the table describes the old algorithm; from Phase 3 on I0 and I3 are asserted zero on every fixture-mode, I1 and I2 on every fixture-mode without a multi-driven port, and the table stays as the record of crossings, bends and size.

**Rationale.** The attempt's counters read the rendered glyphs, which made them depend on `render.zig`'s junction picker and impossible to port to the renderer; these read segments only, so the TypeScript side runs the same definition over its own `buildLayout`. Listing every fixture-mode rather than only the non-zero rows makes the corpus itself visible in the diff — a fixture that stops previewing, or a new one, shows up as a row, not as a silent change of the totals. A per-net definition (rather than per-wire) is what lets a fan-out trunk share its own cells without being counted.

**Alternatives.** Keeping the attempt's glyph-based I2/I3 (render-coupled, not portable); a ratchet that only refuses increases (Phase 3 makes zero a hard gate instead, decision 10); pinning only the totals (hides which fixture moved).

### Long edges get dummy nodes, and a leftward edge is a back edge

**Decision.** `lib/preview/layout/layering.zig` assigns layers exactly as `columns.zig` assigned columns (longest path over the non-back edges, `input_pin` at 0, sinks forced to the last layer, a node fed only by back edges bumped to 1), then splits every forward edge spanning `k > 1` layers into `k` layer-adjacent `LayerEdge`s through `k − 1` dummy nodes (`LayerNode.real == null`, `carries` = the original edge). Every edge that closes a DFS cycle, and every edge that sink-forcing turned leftward (an `led` driving a gate), is flagged `back` on its `OriginalEdge`: no dummies, no `LayerEdge`, routed later as a return lane.

**Rationale.** The greedy router's blindness was structural: a wire spanning three columns was routed through two gutters that knew nothing about it until it arrived. With a dummy per intermediate layer the ordering sees the wire's row against every crossing it causes, the coordinate stage can give it a row of its own, and the channel stage sees it as an ordinary net in every gap. Keeping the layer values identical to the old columns made the first slice a byte-identical checkpoint, which is what let the corpus prove the dummies changed nothing they should not. The leftward-sink rule was found by the corpus, not designed: `regression_led_out_drives_gate` fired the `l_dst > l_src` assert on the first run.

**Alternatives.** Network-simplex layering (fewer dummies; deferred — every golden would move twice); routing long edges without dummies (the attempt's approach, measured and rejected in the plan prompt); not forcing sinks to the last layer (a layout convention the render goldens and the site's readers rely on).

### Ordering is port-aware barycenter sweeps with integer arithmetic

**Decision.** `ordering.order` starts from node-index order (real nodes by id, then dummies), runs rounds of a down sweep and an up sweep sorting each layer by the barycenter of its neighbours' keys — `pos * SLOT_KEY_BASE + slot`, the slot being the sink's input-port index from `ports.zig` so `a` above `b` is a constraint rather than a tie — keeps a round only while `countCrossings` falls (at most four rounds), then transposes adjacent pairs while the crossings around the layer strictly fall (at most sixteen passes). Barycenters are `(sum, count)` pairs compared by cross-multiplication; a node with no neighbours in the sweep's direction keeps its current key; equal barycenters keep the current order. `countCrossings` is the bilayer count over edge-end keys and is the `C=` column of `tests/fixtures/preview/layout-invariants.golden`.

**Rationale.** The old two-sweep barycenter over real nodes with `f64` and id tie-breaks had no port model, so two wires into one `and` counted as parallel however their sources were ordered, and it never checked whether its second sweep helped. Counting crossings with ports lowered `C` on 53 of 223 fixture-modes and raised it on none against the old order lifted into the same measure. Integer pairs exist for the TypeScript port: identical `f64` results are likely but not guaranteed across a refactor, identical integer comparisons are.

**Alternatives.** Median instead of barycenter (Gansner et al.; no measured need); more rounds (the corpus converges in one or two); a global crossing minimisation (out of proportion for these graphs).

### Every node gets its own row, aligned to the port that feeds it

**Decision.** `lib/preview/layout/coords.zig` replaces `place.zig`. Walking layers left to right and each layer's nodes in the ordering, a node's preferred top row is the one that makes the wire into its highest input port (`a` before `b`, `addr` before `din`) a straight horizontal — the source's output-port row minus the port's own row offset — and it is placed at `max(cursor, preferred)`, the cursor advancing past the box plus `ROW_GUTTER = 1`. A dummy prefers its source's port row exactly and is a wire row: it pays no gutter on either side, so a long edge runs straight through the columns it crosses on the free row under a box when that is where its source is. A reverse pass, right to left, moves a node with exactly one out-edge *down* to straighten that wire when its own input wire is not already straight and the node below leaves room; nothing ever moves up. Columns are each layer's widest box plus a per-gap `ChannelWidths.after[k]` (stubbed at the old `5` until channel routing measures demand); `insertSpacerRow` shifts everything at or below a row by one for the channel stage. `boxes.zig` holds the sizes, labels and port coordinates (over `ports.zig`) that `toPlaced` uses to materialise the `PlacedComponent` list.

**Rationale.** Per-grid rows could not put a NOT where an AND's `b` port needed it: `and_of_not`'s fused rail was a placement problem the old router was left to fake. With per-node rows the corpus went from 1013 straight wires to 1963 of 3759, rising on 161 fixture-modes and falling on none, and `and_of_not` renders clean before any routing change. Preferring the input alignment over the output alignment, and moving only down, keeps the pass a single deterministic sweep with no oscillation; Brandes–Köpf's four orientations and balancing were not needed to get there. Charging dummies no gutter brought the corpus height sum back to within four rows of the old grid (`sum(height)` 4941 → 4945) after the first cut had added 190.

**Alternatives.** Keeping grid rows and widening gutters (the attempt's direction; measured and rejected in the plan prompt); the median of all in-edges instead of the highest port (`TODO(phase2)`; not needed for the corpus); full Brandes–Köpf (four alignments plus balancing — more code for a benefit the corpus does not show); allowing the reverse pass to move up (would undo forward alignments and needs a fixed-point loop).

### Wires are routed per gap, on tracks, under a constraint graph

**Decision.** `lib/preview/layout/channels.zig` replaces `route.zig`. Each inter-layer gap is a channel. A *net* is one source port and every sink it reaches in the next layer (a dummy's out-edge belongs to the wire it carries). A net whose terminals all share one row is a straight horizontal; every other net gets a vertical track covering its terminal rows, assigned by the left-edge rule — nets in a topological order of the constraint graph, the lowest track above every predecessor's on which no occupied interval touches the net's. The constraint graph has an arc `A → B` when A's source rail and B's sink rail share a row: A's track is then left of B's, so neither horizontal reaches the other net's corner. A cycle is broken by splitting the widest stuck net at a free row (a dogleg), or by inserting a spacer row through `coords.insertSpacerRow` and planning again when no row is free. A back edge is two half-nets — down a track of the gap after its source to a return row below the diagram, along it, up a track of the gap before its sink — and every layer has a gap so a back edge out of the last layer has one. A gap is `tracks + 2` cells wide, never under five, fed back into the coordinate stage's columns; the plan runs on stub widths (rows only), the columns are laid out again, and the wires are emitted on the result. A net no track can hold goes through a bounded direction-aware cell search over the cells the other wires left free, and is counted (`F=` in the invariants table). `crossings` are computed from the emitted cells: every cell two nets share (render's `┼`) and every same-net cell where one wire corners while another passes (a fan-out tap, render's `●`).

**Rationale.** The greedy router's failures were all one failure: each wire was placed knowing only the wires before it. A channel sees every net that crosses it before placing any, and the constraint graph is the exact condition for "no rail overlaps and no corner lands on another net's cell", so the invariants hold by construction rather than by repair: over the 223-fixture-mode corpus, no wire cell inside a box, every net a tree, and no shared cell or junction anywhere the topology itself does not drive one port from two nets. Demand-sized gaps are what let `stress_grid_10x10`'s twenty input trunks each have a column. Two of 1158 gaps needed a dogleg, none a spacer row, none the fallback search.

**Alternatives.** Visibility-graph A* per connector (libavoid; the right tool for fixed node positions, greedy in the same way as the old router when the layout owns the positions — kept only as the counted fallback); PathFinder-style negotiated congestion (a repair loop for a problem the channel model does not have); widening the old gutters (the attempt; measured and rejected in the plan prompt).

### A macro port the topology cannot name is one port

**Decision.** The collapse stage maps every subcircuit input port whose name is not `a`, `in` or `b` onto `in` (`collapse.zig:remappedPort`), so a parametric macro with inputs such as `data` and `select` receives two nets on one port cell. The router draws both rails to that cell; the invariants table shows their shared cells and the junction, and `corpus_layout_invariants` exempts I1/I2 exactly on fixture-modes with such a multi-driven port (computed from the layered graph, never listed by name). I0 and I3 are asserted zero everywhere.

**Rationale.** Two wires ending on one cell share it whatever the router does; the only fix is a box with one port row per named macro input, which is a change to collapse, sizing and the port tables — out of this initiative's scope by the plan prompt's constraints. Exempting by cause keeps the gate honest: a new fixture with the same shape is exempt, a routing regression on any other fixture is not.

**Alternatives.** Listing the six fixtures by name (silently stale the day a seventh appears); dropping the I1/I2 gate (the property the rewrite exists for); fixing collapse now (a feature, not a repair).
