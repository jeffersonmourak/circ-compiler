# preview-layout

The entries below record the decisions of the layout-rewrite initiative: the ASCII `--preview` layout in `lib/preview/layout/` and its TypeScript port in `circ-renderer/src/layout/` are rebuilt as a layered-graph layout with channel routing, and must produce the same `LayoutGrid`. The fifteen decisions locked at plan time are in `DOCS/PLANS_PROMPT.md`; each phase appends the ones it exercises here as it ships them. The render conventions the layout feeds are in `DOCS/preview.md`.

### The parity contract is a JSON projection, not either side's native type

**Decision.** `lib/preview/dump_json.zig` emits a `LayoutGrid` as JSON with camelCase keys over the common field set of both grids — `width`, `height`, `components[] { id, kind, name, x, y, width, height, inPorts[] { portName, coord }, outPort, bitWidth }`, `wires[] { srcId, srcPort, dstId, dstPort, segments[] { from, to } }` — and nothing else. `kind` is `{ tag: "primitive", kind: <u8> }` in the wire-format numbering (`lib/topology/format.zig`, mirrored by the TS `ComponentKind` enum) or `{ tag: "subcircuit", subcircuit }`. Formatting is fixed (two-space indent, one component or wire per line) so a golden diffs per component and per wire. `tests/preview/layout_conformance_test.zig` pins one file per previewable fixture-mode under `tests/fixtures/preview/layouts-json/`; `circ-renderer/test/layout-parity.test.ts` projects `buildLayout()` onto the same shape and compares vendored copies. Zig's types are untouched.

**Rationale.** The two grids are not the same type and should not be forced to be: `origin` and `display_label` are render-only, `slice` / `memory` aux and `realSrcId` exist only in TS, and `crossings` is derived data the two sides have classified differently. Comparing the projection compares what a reader sees — box geometry and wire paths — and identical segments imply identical crossings once both sides derive them the same way (Phase 3, decision 11). Hand-emitting avoids `std.json`'s snake_case struct output and keeps the file diffable.

**Alternatives.** Comparing the existing text dump (`dump.zig`; not parseable from TS without a second parser); adding TS-only fields to the Zig structs; asserting parity in Zig by re-implementing the TS router (the drift the contract exists to catch). This entry is carried over unchanged from the discarded incremental attempt (`layout-v1-attempt`), whose contract it was.

### The corpus invariants are the measurement of record

**Decision.** `lib/preview/layout/invariants.zig` counts, over a `LayoutGrid` and without rendering, four invariants and four measurements: I0 wire cells inside a component body, I1 cells two or more nets cover with the same orientation, I2 cells where two or more nets meet other than as a clean perpendicular pass-through, I3 nets whose cells are not one 4-connected set from their source cell (or whose wires have a broken or non-axis-aligned segment chain), plus crossings, bends, straight wires and the wire count. A *net* is `(src_id, src_port)`; a net may share cells with itself freely. `tests/preview/layout_conformance_test.zig` writes one line per previewable fixture-mode — every one, zero rows included — and a totals line into `tests/fixtures/preview/layout-invariants.golden`, and the corpus JSON goldens beside it; both are regenerated with `UPDATE_GOLDENS=1 zig build test` and reviewed like any other golden. Until Phase 3 lands the table describes the old algorithm; from Phase 3 on I0–I3 are asserted zero and the table stays as the record of crossings, bends and size.

**Rationale.** The attempt's counters read the rendered glyphs, which made them depend on `render.zig`'s junction picker and impossible to port to the renderer; these read segments only, so the TypeScript side runs the same definition over its own `buildLayout`. Listing every fixture-mode rather than only the non-zero rows makes the corpus itself visible in the diff — a fixture that stops previewing, or a new one, shows up as a row, not as a silent change of the totals. A per-net definition (rather than per-wire) is what lets a fan-out trunk share its own cells without being counted.

**Alternatives.** Keeping the attempt's glyph-based I2/I3 (render-coupled, not portable); a ratchet that only refuses increases (Phase 3 makes zero a hard gate instead, decision 10); pinning only the totals (hides which fixture moved).
