# Plan Prompt — Native Memories (ROM & RAM, host-loaded contents)

## What Is Being Built

The circ language grows two native memory primitives, `rom` and `ram`, declared with the shape the grammar already parses today — `rom code[8, 4] (addr = pc)` and `ram data[8, 4] (addr = a, din = d, we = w, clk = clk)`, where `[W, A]` is the existing `CallWidths` production read as `[data_width, address_width]`. There are **zero changes to `lib/grammar/proto-circ.peg`** (verified empirically: both forms parse cleanly and fail only at name resolution with `E001`). Memories are engine primitives, not gate macros — a flattened gate expansion of even a 256×8 RAM would put tens of thousands of width-1 components into the topology. **Memory contents never appear in source.** They are runtime configuration: a host loads and reads back contents through new WASM exports (`getMemInfo`, `memBuffer`, `memLoad`, `memStore`, `memClear`, `setMemWord`, `getMemValue`, `getMemDefined`), and `--sim` gains a repeatable `--mem=<name>=<path>` preload flag plus interactive verbs (`mems`, `load`, `save`, `peek`, `poke`, `mem`, `clear`) addressed by declared name. The on-disk/in-transit currency is a headerless raw image of little-endian words (`ceil(W/8)` bytes per word), so an assembler's `.bin` or a `printf`-built file loads with no converter. Unloaded and unwritten cells read as undefined (`defined = 0`) through the existing `BitVecState` story.

Semantics locked during discovery: **ROM is purely combinational** — `out = cells[addr]`, any undefined address bit yields a fully undefined output, re-evaluated through the normal `recalculateAndReschedule` path at gate delay. **RAM is single-port with asynchronous read and clocked edge write** — the write commits inside the RAM's own recalculation arm when `clk` transitions from *defined low* to *defined high* (an X→1 transition is not an edge), `we` is defined-high, and `addr` is fully defined; `prev_clk` is stored on the payload *before* acting so the detector is idempotent across Phase 2's multiple recalculations per timestep. The clock is an ordinary width-1 input pin the host pulses with `setPin` — no clock language construct, no `tick()` export. Host-side content mutations all end in one `memoryRefresh` that recomputes `out` with the same function the recalc arm uses and calls `propagateEvent` only when the value differs under `BitVecState.equals`, so a load that does not touch the presented address neither enqueues nor bumps `current_time`. The initiative ships the language front door first (every emitter rejecting cleanly), then the engine as a pure library, then topology v03 + runtime + WASM exports together, then `--sim`/`--truth-table` ergonomics, then golden coverage and classroom docs.

Definition of done: both declaration forms compile to self-contained `.wasm` artifacts whose new exports load, mutate, and export memory contents; `--sim` preloads from files and drives memories by declared name; `--truth-table` tabulates preloaded ROMs and rejects RAMs with an explicit message; `--inspect`, `--analyze`, and `--preview` handle both kinds; `--emit-zig` rejects them cleanly; diagnostics `E017`/`E018` are appended with fixtures and every existing code that gains a memory arm (`E002`, `E004`, `E006`, `E011`, `E014`) is covered; behavioral (`expected-wasm`) and `--sim` transcript goldens exist for a ROM lookup and a RAM write/read; `DOCS/language.md`, `circuit-format.md`, `wasm-api.md`, `sim-protocol.md`, and `decisions/language.md` document the surface and record the decisions below.

## Architectural Constraints

Frozen surfaces and repo rules:

- **Wire kind encodings are append-only** in `lib/topology/format.zig` (`ComponentKind`: input_pin=0, not=1, and=2, wire=3, led=4, output_pin=5, slice=6, concat=7). Memories take `rom = 8`, `ram = 9`. Note `lib/circuit.zig` `toKind` and `lib/transport.zig` `kindByte` use a *different, wrong* numbering (led=2/and=3/wire=4) that CLAUDE.md repeats — `toKind` is dead code (no callers) and is deleted, not extended; `transport.kindByte` gets 8/9 arms; CLAUDE.md's table is corrected in the same change.
- **`PortName` is a closed `u8` enum** (`in/a/b/out` = 0..3). Append `addr = 4`, `din = 5`, `we = 6`, `clk = 7` and update every byte↔name mapper: `serializer.parsePortName`, `full_serializer.parsePortByte`, `interpreter.portNameStr`, `engine_session.portByteToName`, `preview/dump.portName`, plus `Circuit.connect`. A missed mapper surfaces only as `init()` swallowing `InvalidPort` and every export silently returning 0.
- **Topology format bumps `0x02 → 0x03`** in both `format.VERSION` and `full_format.FULL_VERSION`; both readers (`templates/interpreter.zig:26`, `lib/topology/full_decoder.zig:52-53`) reject anything else, and tests must prove v02 is rejected.
- **Diagnostic codes are append-only from `E017`** (`lib/validator/codes.zig`, guarded by `tests/validator/codes_snapshot_test.zig`). An enum member without a `templates` row compiles and hits `unreachable` at runtime — add member, row, and fixture in one commit.
- **No allocator parameters on the engine.** `memory.allocator` is an `ArenaAllocator` over `page_allocator` on every target (`lib/memory.zig:65-71`; CLAUDE.md's "wasm_allocator / GPA" description is stale and gets corrected). `free` only rewinds the most recent allocation, so per-memory buffers are allocated once and reused.
- **One engine node per memory record, created in the interpreter's record loop.** Hosts index `runtime_circuit.nodes.items[id]` by array position (`templates/main.zig:46-48`); the serializers assign dense ids in append order. Helper nodes inside the record loop would silently shift every later id.
- **One output port per component** (`Component.outputs` is a flat list). Memories expose only `out` = the asynchronous read; single-port only.
- **Cells live on the component payload as two `[]u64` planes** (`values`, `defined`, length `1 << A`), *not* in the width-tiered pool. This is a deliberate choice, not a structural necessity (verification showed the pool can host a contiguous run of `2^A` tier-W slots): planes give one contiguous allocation per plane, a flat buffer the WASM load/export path can `memcpy`, and no coupling of memory size to pool growth or tier-1 bit-packing. The `out` port stays an ordinary tier-W pool slot so `width = state_handle.tier` (`lib/circuit.zig:68`) keeps holding.
- **Width bounds:** data width `W ∈ [1, 64]` (`BitVecState` cap), address width `A ∈ [1, 16]` (65,536 words; ~1 MiB of planes plus a staging buffer per memory in the arena). Larger literals are `E018`; note that any width literal `> 255` currently makes the whole declaration vanish silently (`translate.zig:161`, `:696 catch {}`) — a pre-existing hole, documented not fixed here.
- **`rom`/`ram` become reserved builtin type names** in all three reserved-name lists: `resolver.isPrimitive`-adjacent check (`lib/ir/resolver.zig:93-103`, evaluated *before* import aliases), `name_collision.isBuiltinName` (`E006` for instances/inputs), and `scan_imports.isBuiltinAlias` (`E011` for `import rom "…"`). Without the last one an existing `import rom` degrades to a non-blocking `W003` and the primitive silently replaces the user's sub-circuit.
- **Memory validation lives in the single-file resolver + `validator/run.zig` passes**, not in `resolve_bodies` — `--inspect` never runs project resolution (`cmd/circ-compile/main.zig:210`), so anything placed next to `E015`/`E016` is invisible there and in single-file tests.
- **`--sim` stdout is the protocol channel and the `ready` block stays byte-identical** for every circuit (`ready` + `pin` lines + `diag` lines, `lib/sim/loop.zig:10-12`); memories are discovered with the `mems` verb, never with new handshake line types. Preload failures go to stderr with exit 2 *before* any handshake (mirrors "input file not found", `main.zig:181-188`). `proto` stays `1` — verbs and error codes are additive.
- **Existing scalar `.circ` files stay legal** and untouched goldens stay byte-stable.
- Git conduct per `CLAUDE.md`: stage by path, propose every commit message and wait, never push or attribute.

Locked design decisions (to be recorded in `DOCS/decisions/language.md` and `decisions/runtime-api.md` in Phase 4):

1. **Engine kind:** a single `ComponentType.memory` with `mode: enum { rom, ram }` on the payload; the wire format keeps two kinds (8/9) and the IR one variant `memory { mode, data_width, addr_width }`. Every *policy* site (cycle-breaking, required ports, truth-table rejection, preview glyph) dispatches on the IR or wire kind; the engine differs only in which ports `connect` accepts and one `if (mode == .ram)` block in the recalc arm.
2. **Image format:** headerless, `bpw = ceil(W/8)` bytes per word, little-endian, word `i` at `[i*bpw, (i+1)*bpw)`, bits `≥ W` must be zero (strict `WordExceedsWidth` — padding bits are the only wrong-width symptom detectable without a header), `len % bpw == 0`, `len / bpw ≤ 2^A`. Undefined is not representable on disk; export writes `value & defined`. Codec in `lib/memimage.zig`, imported relatively from `circuit.zig` (as `transport.zig` is) so `build.zig` and the runtime module set are untouched. No magic sniffing, ever (a raw image may legally begin with any bytes).
3. **Load semantics: replace-all.** A short image leaves cells `n..2^A-1` undefined; an empty file equals `clear`.
4. **WASM exports** (appended to the `comptime { @export }` block, `templates/main.zig:74-81`; additive — no host or test enumerates exports, and the Debug runtime already leaks ~34 `__ubsan_*` symbols):
   - `getMemInfo(id) -> i32`: `(kind << 16) | (W << 8) | A`, or `-1`.
   - `memBuffer(id) -> i32`: pointer to a per-memory staging buffer of `bpw << A` bytes, allocated once lazily; hosts re-view `memory.buffer` after the call.
   - `memLoad(id, len) -> i32`, `memStore(id) -> i32` (bytes written), `memClear(id) -> i32`, `setMemWord(id, addr, value, defined) -> i32`.
   - `getMemValue(id, addr) -> i64`, `getMemDefined(id, addr) -> i64` (paired, return 0 on error like the existing getters).
   - Status codes: `0` ok; `-1` uninitialised/bad id/not a memory; `-2` length not a word multiple; `-3` word exceeds width; `-4` too many words; `-5` `len` exceeds staging size; `-6` `memBuffer` never called; `-7` address out of range. A status on every mutator matters because `init()` swallows errors and hosts have no other signal.
5. **Edge rule:** `rising = clk is defined-high && prev_clk is defined-low`; `prev_clk` updated before acting; write iff `we` defined-high and `addr` fully defined; `din` stored masked to `W`, partial-X `din` stored as-is. Read `we`/`clk` with a width-agnostic bit test (`(s.defined & 1) != 0 and (s.value & 1) != 0`) or have `connect` reject non-width-1 drivers — `isHigh`/`isLow` assert `width == 1` and the runtime is a Debug build, so a malformed topology would trap.
6. **E008:** `ram` is cycle-breaking (same class as `and`/`not` in `combinational_loop.zig:15-22`); `rom` is not. The pass is component-granular everywhere; no port-aware rewrite.
7. **`--sim` preload and verbs:** `--mem=<name>=<path>` (split at the first `=` after the prefix, fixed-capacity `[16]` on `Args` so `parse` stays allocator-free, `TooManyMemPreloads`, scoped to `sim` and `truth-table`); verbs `mems`, `load <mem> <path>`, `save <mem> <path>`, `peek <mem> <addr>`, `poke <mem> <addr> <value> [<mask>]`, `mem <mem> [<start> [<count>]]`, `clear <mem>`; error codes `E_NOMEM`, `E_IO`, `E_MEMFMT`, `E_ADDR` (reuse `E_WIDTH`/`E_BADVAL`/`E_PROTO` for `poke`). Paths are whitespace-free (tokenizer) and resolved against the cwd; `load` is the loop's first filesystem access. `reset` re-applies CLI preloads and drops mid-session `load`/`poke`. Root-level memories only (`origin.len == 0`, mirroring pins); nested ones stay id-addressable from a WASM host.
8. **Tooling policy:** `--truth-table` allows ROM (`BuildOptions.preloads` via `--mem`; unloaded cells render `?`, `--strict` fails them; `countInputBits` untouched) and rejects RAM at `builder.build` pre-flight with `error.StatefulComponent` and an explanatory message. `--preview`: ROM = 1-input box, RAM = 4-input box on the `and_gate`/macro port pattern, label `rom code[8,4]`. `--analyze`: `symbolKind` rom/ram + hover in Phase 0, optional `addr_width` JSON field in Phase 4. `--emit-zig`: pre-flight rejection (`--emit-zig does not support rom/ram; compile to .wasm instead`). Bench untouched.
9. **`--inspect`:** IR line `kind=rom[W=8,A=4]` and AST line `widths=[8, 4]` only. No "global id" block — inspect's ids are resolver-local; hosts learn memory ids from the v03 `.full` section (kind 8/9 record, `name`, empty origin). A proper name→global-id listing for hosts is a separate follow-up.
10. **Topology v03 records:** `.min` memory record = `id u32 | kind u8 | width u8 (= W) | addr_width u8` (7 bytes, dispatched by kind exactly like slice's 2-byte suffix; `ComponentRecord.aux_lo` carries `addr_width`); `.full` gains `Aux.memory { addr_width }`. Connections unchanged (port byte is a `PortName` for memories, never an operand index).
11. **Validation:** `E017` "memory parameter list malformed" — not exactly two width arguments (`rom m(…)`, `rom m[8](…)`, `rom m[8,4,2](…)`, the `IdentList` form `rom a, b`, any anonymous inline form, and a type-position width `rom[8] m[8,4]`), with a message showing the correct shape. `E018` "memory width out of range". Reused with new arms via one `memoryPortWidth(mem, port)` helper (addr=A, din=W, we=1, clk=1, out=W): `E002` unknown port, `E004` required input unconnected, `E014` width mismatch (today `E014` fires only primitive↔primitive on `Component.width`, `port_validation.zig:99-110`). `E006`/`E011` reservations as above. The `rom`/`ram` branch in `addComponent` must call `widthFromSpec` on `width_args[0..2]` explicitly — it is wired only to `type_name.width` today (`resolver.zig:105`) — which is what makes `rom m[W, A]` inside a `<W, A>` sub-circuit bind for free.

## Working Loop

The execution agent follows this loop every session without exception:

### On Cold Start

1. Read this file (`DOCS/PLANS_PROMPT.md`) in full.
2. Read `DOCS/STATUS.md` (if it exists). The latest entry defines what was last shipped and what comes next.
3. Run `git log --oneline -10` and `git status`. If STATUS claims a slice is committed but it does not appear in `git log`, the human has not committed yet — **do not begin a new slice**. Stop and say so.
4. Read the active phase plan (`DOCS/PLANS/PHASE_<N>_<name>.md`) for the current phase.
5. Implement the next slice per the phase plan. Do not start a second slice until the first is reviewed and committed.

### Each Slice

1. Implement the full slice as specified. Do not stop mid-slice.
2. Run the project's test command for the affected modules. Do not ship a slice that breaks the suite.
3. Append a STATUS entry (template below).
4. Stage the slice's files (`git add <files>`).
5. Display the proposed commit message and **stop**. Wait for explicit human approval before running `git commit`. Do not begin the next slice until the commit is confirmed and made.

### Git Rules

- Read-only git commands (`status`, `log`, `diff`) are encouraged for situational awareness.
- **Committing:** At the end of a slice — and only at the end of a slice — the agent stages the slice's files (`git add <files>`), then displays the full proposed commit message to the human and waits for explicit approval before running `git commit`. Staging first lets the human inspect the diff in any git client before approving. Do not commit without that confirmation.
- Do **not** push, force-push, amend, rebase, reset, delete branches, or run any other write `git` or `gh` command under any circumstances.

## Recurring Traps

- **Three kind numberings exist.** `format.ComponentKind` is the wire truth (and=2, wire=3, led=4); `circuit.toKind`, `transport.kindByte`, and CLAUDE.md say led=2/and=3/wire=4. Allocate 8/9 from `format.zig` only.
- **Exhaustive vs. `else`-guarded switches.** The compiler forces arms in `interpreter.zig`, `engine_session.Session.build`, preview sizing, and `portNameStr`; but `required_input`, `combinational_loop`, `serializer.zig:169/263`, `full_serializer.zig:180/331`, `full_decoder.zig:100`, `truth_table`, and `emit/project` have `else` arms that compile unchanged and *silently ignore* memories — each needs a deliberate decision. The decoder's `else => .none` in particular makes `engine_session`'s `.memory` aux lookup fail at runtime if forgotten.
- **`init()` swallows every `initFromTopology` error** (`templates/main.zig:29-32`): a missed `PortName` mapper, a stale runtime, or a v02/v03 mismatch shows up only as every export returning 0. Memory mutators returning status codes are the host's one diagnostic.
- **`memoryRefresh` must guard with `BitVecState.equals`** — the same predicate as the Phase-1 dedup. A looser compare enqueues an event that Phase 1 then dedups, but `current_time` is already advanced at `circuit.zig:741`: a spurious bump by a different path. The event queue must be empty when a host hook runs (true for all current entry points; not inside a listener callback).
- **`recalculateAndReschedule` takes `circuit: *const`**: the RAM write inside the arm must mutate component-owned storage via a `|*ram|` capture, never `Circuit.writeState`.
- **`std.PriorityQueue` is timestamp-ordered but not stable.** Never enqueue divergent same-timestamp events for one component; today this cannot happen only because hosts settle between drives.
- **The arena never frees.** Every `--sim reset` rebuilds the `Session` and leaks the planes (~1 MiB per A=16 memory); `memBuffer` must allocate once. A later `Circuit.reset()` reusing planes is the fix, out of scope here.
- **`--sim` returns before the `-Werror` check** (`main.zig:278` vs `:305`); memory diagnostics must come from the validator before `:279` to appear in the handshake.
- **`Args.parse` is allocator-free and returned by value**; threading an allocator through it touches ~40 parse tests — hence the fixed `[16]` preload array.
- **`--inspect` runs single-file resolution only**; its `id=` values are resolver-local and are not runtime ids for project circuits.
- **Width literals `> 255` vanish silently** at translate time (u8 parse, `catch {}`), so `E018` can never fire for them.
- **A third topology reader lives outside the Zig code:** `site/node_modules/circ-renderer/src/wasm/topology.ts` is pinned to `FULL_VERSION = 0x01` and already incompatible with v02. Do not recompile the committed `site/public/wasm/*.wasm` (still v01) until the renderer is updated.
- **Two Node harnesses read `expected-wasm/`:** `serializer_fixtures_test.zig:198-207` is scalar-only (`value==1?1:0`, `===0n?0:1`); `section_writer_fixtures_test.zig:39-66` already speaks MSB-first `0/1/?` bit-strings. Neither has a preload vocabulary — the `mem` preamble in Phase 2 lands in the latter and is real scope, not "add a fixture".
- **The `--sim` tokenizer splits on whitespace** (`protocol.zig:85`): paths with spaces are unsupported; document rather than invent quoting.
- `UPDATE_GOLDENS=1` regenerates in place — diff before committing; untouched fixtures must stay byte-identical.
