## Goal & scope

`circ-compiler` becomes usable without installing it. The front end behind `cmd/circ-compile/main.zig`'s mode dispatch was lifted into a library, `lib/libcirc.zig` (+ `lib/libcirc/{frontend,modes,json,c_api,wasm_root}.zig`), that takes an in-memory project (`{"root": "/playground/main.circ", "files": {"<virtual path>": "<text>"}, "options": {…}}`) and returns exactly what the CLI prints — a self-contained `.wasm` artifact, `--analyze` JSON, `--preview` text, a truth table — through one C ABI built two ways: `zig build libcirc` (`libcirc.a` + `include/libcirc.h`) and `zig build libcirc-wasm` (one `wasm32-freestanding` module, ReleaseSmall and stripped, embedding the runtime it was built with). The site (`site/`, static Astro, bun-only deploy) gained `/playground`: a Web Worker owns `libcirc.wasm`, a textarea drives analyze/compile/preview/truth-table on a 250 ms debounce, and `circ_compile`'s bytes go straight into `circ-renderer`'s `renderCircuit({ bytes })` path — entirely client-side, no server, no CLI. The one hard blocker was the parser: a langlang-generated Go program linked as a CGo c-archive, with no route from Go to `wasm32-freestanding`, so the locked direction was that **langlang itself generates the parser straight to Zig** (the maintainer's fork's `-output-language zig`, pinned to upstream `go/v0.0.12`, installed as `v0.0.13-zig.2`), vendored as `lib/parser/parser.zig`, with Go, the c-archive, and the Go prerequisite leaving the repo in the same phase. Constraints that shaped the work: `translate.parseSource`/`parseSourceCapturing` are frozen signatures, and `ast.zig` + `tests/helpers/ast_dump.zig` output is the parser's golden contract (the only permitted change being Phase 0's additive `Errors (n)` section); every `expected-*` golden stays byte-identical through Phases 1–5, and parser quirks are pinned, not fixed; `--analyze` JSON stays byte-compatible because `circ-lsp` parses it, and libcirc's status-1 result *is* that shape; diagnostic codes are append-only and libcirc adds none; no allocator parameter on the engine — `memory.reset()` (`arena.reset(.free_all)`) is the single permitted addition; `format.zig`/`full_format.zig` own the topology versions with no compatibility shim in the compiler, so the renderer follows the compiler in one commit per version; `--sim`, `--emit-zig`, and `--inspect` stay CLI-only; the site stays bun-only with the wasm artifacts committed.

### Phase 2 — Host-free front end, `lib/libcirc.zig` driver, native static library

A host hands the compiler an in-memory project and gets back exactly what the CLI prints — with no disk access when every file is in the overlay — while `circ-compile` is re-based on the same Zig API with every stderr string, exit code, and golden unchanged.

- **Overlay-first loading:** `lib/resolver/file_loader.zig` consults the overlay by a normalised key (`normalizeKey` = `std.fs.path.resolvePosix`) *before* `realpath`; `resolveImportPath` gained an `overlay` parameter and joins with `resolvePosix`; disk branches compile out on `.freestanding` (`has_disk`) and fall through to `error.FileNotFound` → `E009`. One observable change on native: `files[].path` for an overlay-keyed file is now the normalised key, not its realpath — `--analyze` consumers (`circ-lsp`) get back the key they sent; `DOCS/analyze-api.md`'s `overlays` bullet documents it.

## API surface frozen by the plan

**Diagnostic codes and CLI flags: unchanged.** This plan appended nothing to `lib/validator/codes.zig` (still `E001`–`E018`, `W001`–`W003`) and added no `circ-compile` flag; the new surface is the ten `circ_*` exports, the request JSON, and the `-Dwasm-optimize` build option below.

### The ten `circ_*` exports (`lib/libcirc/c_api.zig`, `include/libcirc.h`)

In this order; identical surface for `libcirc.a` and `libcirc.wasm` (`export fn`, `callconv(.c)`, pointer-sized `ptr`/`len` — `uint8_t*`/`size_t` in the header, `i32` in the wasm32 signature).

| Export | Contract |
|--------|----------|
| `circ_alloc(len)` | Request buffers; caller frees with `circ_free`. `circ_alloc(0)` returns a static in-bounds byte. |
| `circ_free(ptr, len)` | Frees a request buffer; `len == 0` is a no-op. |
| `circ_version()` | Status 0; result is one JSON line with exactly seven keys: `version`, `revision`, `topology_version`, `full_version`, `parser`, `parser_runtime_sha256`, `grammar_sha256`. |
| `circ_analyze(req, len)` | `analyzer.renderJson` bytes (the `DOCS/analyze-api.md` shape, trailing `\n`). |
| `circ_compile(req, len)` | The self-contained `.wasm` bytes (`section_writer.combineTwo` output). |
| `circ_preview(req, len)` | `--preview` text with `color` per options. |
| `circ_truth_table(req, len)` | Markdown / CSV / JSON table text; calls `memory.reset()` after rendering. |
| `circ_result_ptr()` | Library-owned result buffer; valid **only** until the next `circ_*` call. |
| `circ_result_len()` | Length of that buffer. |
| `circ_reset()` | Drops the result buffer, the call arena and the engine arena (`memory.reset()`); returns 0. |

**Status codes** (`CIRC_STATUS_OK` … `CIRC_STATUS_INTERNAL` in `include/libcirc.h`): `0` ok · `1` front-end diagnostics in the analyze-api shape (`{"files":[…],"diagnostics":[…],"symbols":[],"references":[]}`) · `2` bad request (`{"error":"…"}`) · `3` mode refusal (`{"error":"…"}`: input-bit cap, stateful-RAM truth table, bad preload, layout failure) · `4` out of memory (result empty) · `5` internal (`{"error":"<stage label>: <ErrName>"}`). The C ABI is **not** thread-safe: `result_buf`, the call arena, and the engine arena are process globals.

**wasm module surface** (`zig build libcirc-wasm`): exports exactly `circ_alloc circ_analyze circ_compile circ_free circ_preview circ_reset circ_result_len circ_result_ptr circ_truth_table circ_version memory`; imports exactly `env.debugEnabled env.onDebugLog`.

### Request JSON and options

```json
{"root": "/playground/main.circ",
 "files": {"/playground/main.circ": "…", "/playground/half_adder.circ": "…"},
 "options": {…}}
```

`root` is required; `files` must be an object mapping **absolute-looking** keys to strings (keys normalised with `std.fs.path.resolvePosix` and matched byte for byte); any unknown or mistyped key **inside `options`** is `BadOption` → status 2 (unrecognised top-level keys are ignored).

| Option | Values | Applies to |
|--------|--------|------------|
| `expand_macros` | bool (default `false`) | preview |
| `expand_display` | bool (default `false`) | preview |
| `color` | `"never"` \| `"always"` (default `never`; `"auto"` is `BadOption`) | preview |
| `format` | `"markdown"` \| `"csv"` \| `"json"` (default `markdown`) | truth table |
| `value_format` | `"binary"` \| `"hex"` \| `"decimal"` (default `binary`) | truth table |
| `truth_table_cap` | 1..24 (default 16; out of range is `CapOutOfRange`) | truth table |
| `preloads` | `{"<declared memory name>": "<hex image>"}` (non-hex is `PreloadNotHex`) | truth table |
| `warnings_as_errors` | bool (default `false`) — promotes `W*` to status 1 | compile / preview / truth table |

`json.ParseError` members each have a `describe` string: `InvalidJson`, `NotAnObject`, `MissingRoot`, `RootNotString`, `FilesNotObject`, `FileTextNotString`, `FileKeyNotAbsolute`, `OptionsNotObject`, `BadOption`, `PreloadNotHex`, `CapOutOfRange`, `OutOfMemory`.

## Known papercuts carried forward

- **The Linux Node `init()` hang is still open.** `pr-tests.yml` keeps `SKIP_WASM_E2E=1`, so no CI run covers `libcirc.wasm` or the runtime host protocol. The Docker bisect harness landed (`zig build e2e-linux-docker`, `WASM_OPTIMIZE ∈ {Debug, ReleaseSafe, ReleaseSmall} × NODE_IMAGE ∈ {node:22-bookworm-slim, node:24-bookworm-slim}`), but the matrix never ran — `docker build` failed at `FROM node:22-bookworm-slim` with `DeadlineExceeded`, and no Node image was cached. When the matrix does run, capture `shasum -a 256 zig-out/lib/circ-runtime.wasm` on the host in the same session as the container run — every `zig build` rebuilds the artifact, so a cross-host comparison is meaningful only against the run that produced it.
- **The browser-side manual checklist was never run.** Caret placement, debounce feel, the version banner, pin replay across a theme flip, tour step 6's two `// name.circ` blocks, and hash-gated rebuilds are proven only by `bun test` and `bun --bun run build`; no browser was available in any session.
- **The `circ-renderer` PR is not opened.** Branch `host-pin-api` is pushed and pinned (`#6f31ea1`, package `2.1.0-alpha.1`), but merging it into that repo's `main` is the maintainer's to do.
- **`compile` and `--emit-zig` take the import-free fast path**, which does not resolve implicit builtin macros, so a single file using `xor`/`or`/`nand`/`nor`/`xnor` returns `E001: undeclared name 'xor'` while `--preview`/`--truth-table`/`--analyze` on the same file succeed. The playground surfaces this on a reader's first `xor`; whether to change the route table is a decision for the next initiative.
- **The library and the CLI disagree on recovered syntax errors.** `libcirc.compile`/`preview`/`truthTable` return status 1 with `syntax` diagnostics for a file whose declaration was dropped by recovery; `circ-compile` still compiles that file (pre-existing behaviour, deliberately unchanged).
- **`parser:gen`'s version gate is a substring match on one literal** (`expect_stdout_match = "v0.0.13-zig.2"`). A langlang tag bump must change that literal in `build.zig` together with `CLAUDE.md`, `README.md`, and the `lib/grammar/proto-circ.peg` header, or the step silently accepts the wrong generator's ABI.
- **Two `.linkLibC()` calls remain**, on `emit_behavior_tests` and `project_behavior_tests`, purely for `tests/helpers/wasm_run.zig:12`'s `std.c.getpid`. Switching that line to `.linux => std.os.linux.getpid(), else => std.c.getpid()` would retire them, but only with `zig build test-emit` green on the Linux CI job.
- **`build.zig` is still not `zig fmt`-clean.** 17 lines carry pre-existing trailing whitespace (all within `:51-162` at the canonical commit); every slice in this plan applied its hunks without reformatting, so the diffs stayed reviewable. Run `zig fmt build.zig` in its own commit, never alongside a feature hunk.
- **`diff-circ.sh` can no longer prove table equality against this checkout.** The fork's script hardcodes `CIRC_PARSER_GO="$CIRC_ROOT/lib/parser/parser.go"`, which Phase 1 deleted; reruns need `git show 4ce729b:lib/parser/parser.go > <tmp>/parser.go` and the path overridden. A `CIRC_PARSER_GO=${CIRC_PARSER_GO:-…}` default in the fork is the tidy fix.
- **The parser quirks pinned in Phase 0 are still quirks**, fixable only by a grammar edit + `parser:gen` + golden review: keyword-prefix splitting with no word boundary (`andx g(...)` → `and` + instance `x`), trailing whitespace absorbed into a `BaseRef` span, `import x ""` kept with the literal path `"`, width/subscript literals > 255 dropping the whole declaration via `catch {}`, and `output o()` swallowing the following line.
- **Deferred playground UI:** no CodeMirror (a plain `<textarea>` with Tab → two spaces), no draft persistence or `#src=` share links, no `circ_inspect`/Inspect tab, and no memory UI — the page sends no `preloads`, and neither the playground nor the renderer implements loading a ROM image or poking cells from the canvas.
- **The committed manifest's `revision` names the commit before the one that commits it.** It is the compiler `HEAD` at build time, inherent to committing a build product; the example `.wasm` files already behave that way.
- **Local build quirk worth knowing:** `node` on the maintainer's machine is an x64 build under Rosetta, so plain `bun run build` fails in rollup's native loader (`@rollup/rollup-darwin-x64`); use `bun --bun run build`, which is what CI's `oven-sh/setup-bun` effectively does.
