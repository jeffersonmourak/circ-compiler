# Plan Prompt — Playground bench (the playground redrawn as one canvas-first sheet)

## What Is Being Built

The site's `/playground` is a workbench of four bordered panes: a workspace tree, an editor with a two-tab dock (Diagnostics, Settings), an output pane with four tabs (Preview, Truth, Simulate, Data), and a drawer under it with a console and a memory panel; a status bar under everything carries the compiler identity, Download and Share (`site/src/components/Playground.astro`, 3,523 lines; the `.pg-*` rules of `site/src/styles/global.css` at 546–1340 and 1677–2074). Every one of those parts works and is tested, and the whole reads as a grid of boxes. A design handoff under `DOCS/design/design_handoff_playground_bench/` (`README.md` and the boards in `Playground Upgrade.dc.html`) redraws the page as **the bench**: two regions on one sheet — the source on `--pane-bg`, the canvas on `--bg` with a dot grid, one hairline between them — under a 48px nav and over a 40px terminal line and a 24px status line. The workspace tree becomes a project switcher popover from a breadcrumb (board 3a); the dock's Diagnostics tab becomes a footer under the editor (3b); the output tabs become a three-way view switch, Schematic · Live · Truth (3e, 3f); the Data tab becomes a floating panel over the canvas (3d); the drawer collapses to one line and grows to a split console and memory (3c). Same tokens, same fonts, same runtime: the change is CSS and DOM restructuring in `Playground.astro`, with the small amount of new behaviour the boards imply (a search in the switcher, a draggable panel, a truth row that drives the pins, zoom and fit on the canvas).

The renderer already carries what the canvas region needs: the site pins `circ-renderer` at `2d973b4` (`2.3.0-alpha.4`, `RENDERER_PIN_VERSION`), whose `navigation`, `viewport: 'parent'`, `fit()`, `resetView()` and `onViewChange` shipped for exactly this page and are adopted nowhere yet. The compiler and the renderer are read-only for this initiative.

**Definition of done.** The playground renders each of the seven built boards — 2a (the bench, everything closed), 3a (switcher open), 3b (diagnostics footer expanded, a wider program), 3c (drawer open, console beside memory), 3d (Data panel open over the Hack ALU), 3e (Schematic), 3f (Truth with the live row tinted) — in both `data-theme` modes, with the geometry, spacing, type sizes and colour roles the design file's inline styles give; board 1a is not built. Nothing the page does today is lost: every file-tab, tree, console, memory, settings, share, download and source-linking behaviour that `site/test` proves still passes, and the island smoke walks the new DOM. `bun test`, `bun --bun run typecheck`, `bun --bun run build` and `bun run bundle` are green with the `/playground` ceiling unchanged; `DOCS/decisions/playground-bench.md` records every decision below that a phase exercised; the handoff is archived and the plan bundle archived per `DOCS/prompts/ARCHIVE.md` before the branch merges.

## Tech Stack

- **Site:** Astro 5 under `site/`, one island (`Playground.astro`) whose logic lives in pure modules under `site/src/scripts/` and `site/src/utils/` so `bun test` (happy-dom, no canvas, no worker) can drive it. Editor: CodeMirror 6, six exact-pinned packages, theme in `site/src/utils/circ-editor-theme.ts`. Gates, in order: `bun test`, `bun --bun run typecheck`, `bun --bun run build`, `bun run bundle` (`site/bundle-budget.json`: `/playground` raw 368,640 / gzip 122,880). `site/test/island-smoke.test.ts` runs the built island against the built HTML and needs `dist/`; `site/test/app-layout.test.ts` guards that every app-layout rule is scoped to `[data-layout='app']` and none reaches `.lc-mount`.
- **Renderer:** `circ-renderer` pinned at `2d973b4` in `site/package.json` and asserted by `site/test/renderer-pin.test.ts`; its README documents `navigation`, `viewport`, `onViewChange`, `zoomBy`, `fit`, `resetView`. Read-only.
- **Compiler:** Zig 0.15.x, `libcirc.wasm` behind `site/src/workers/libcirc.worker.ts`. Read-only. `lib/truth_table/builder.zig`'s `build` enumerates every input bit and takes no fixed inputs.
- **Design reference:** `DOCS/design/design_handoff_playground_bench/` — `README.md` (the spec), `Playground Upgrade.dc.html` (the boards; needs `support.js` and `_ds/` beside it), `github.md` (the source map), `circ-scenes.js` (harness scenes for the boards' canvases), `_ds/<id>/` (the CircDS bundle and tokens). The DS's `--font-mono-strict` is the site's stack verbatim (`ui-monospace, SFMono-Regular, "JetBrains Mono", Menlo, …`).
- **Style of every doc and every string the page shows:** Strunk & White (the book is in the books-knowledge library).

## Architectural Constraints

- **The playground stays an `app` variant of `Base.astro`** (`DOCS/decisions/playground.md`, "The playground is an `app` layout variant of `Base.astro`"): one layout file, `data-layout="app"` on `<body>`, every bench rule scoped to it, no rule reaching `.lc-mount`. The variant grows the one thing the bench needs — it yields the nav and footer rows to the page (decision 1) — and other pages' markup stays byte-identical.
- **The splitter stays one custom property and a WAI-ARIA separator** ("The splitter is one custom property…"): the source column is the reader's splitter, and the drawer's height is the drawer splitter's. Neither grows a second mechanism.
- **One localStorage key, one schema-versioned envelope** ("One localStorage key…"): every persisted bench state (view, footer open, Data panel position, drawer height) is a field of `PlaygroundEnvelope`; nothing is stored under a second key. `normalize` today resets the whole envelope on a version mismatch (`playground-store.ts:252`), scratch projects included, so the schema moves only by decision 5.
- **One simulation session, and every face drives through it** ("One simulation session…", "The Data tab is rows over the session…", "The console's value spelling is the protocol's"): the Data panel, a truth row click, a canvas pin click and the console all go through `SimSession` and echo in the console as `commandFor` spells them. No face writes the runtime directly.
- **The renderer's hook model stays and the renderer is read-only** (`DOCS/decisions/canvas-theme.md`): the canvas region adopts options the pinned renderer already exports. A need the renderer cannot meet is recorded as a follow-up in STATUS, never a site workaround, and a renderer change is the human's decision, in the renderer's own worktree.
- **Every colour and font in a `.pg-*` rule is a token.** `--bg`, `--pane-bg`, `--code-bg`, `--pane-label-bg`, `--fg`, `--muted`, `--accent`, `--accent-soft`, `--border`, `--font-prose`, `--font-mono`, `--font-mono-strict`, the site-local `--term-ok`, `--term-echo` and the new `--danger` (decision 4). A source-text test enforces it (decision 12), the way `circ-skins.test.ts` holds "every colour a skin sets comes from the palette".
- **The JavaScript budget is per page and never raised silently** ("The JavaScript budget is per page…"): the bench is CSS and DOM; the eager chunk may grow by the new pure modules and no more, and STATUS records the `bun run bundle` numbers for `/playground` in every phase that touches the island.
- **Behaviour a `bun test` can reach lives in a module without module-scope side effects.** The switcher's filter, the diagnostics footer's summary, the Data panel's position clamp, the truth view's live-row match and over-cap rows, the terminal line's summary all land in `site/src/scripts/` with their tests; `Playground.astro` wires them.
- **Accessibility does not regress.** The tree's keyboard model (`ws-tree.ts` `moveFor`), the tab and separator roles, the one `role="status"` announcement channel ("The status bar is a pure function of one input record"), the live console log, and every `aria-label` the smoke test reads survive the restructuring; a popover and a floating panel add `aria-expanded`, `Escape` to close and focus return.
- **Documentation lands with the code** ("Documentation lands with the code"): each phase appends its exercised decisions to `DOCS/decisions/playground-bench.md` (registered in `DOCS/decisions/index.md`); `DOCS/sim-protocol.md:230-235` names the Simulate and Data tabs and is reworded in the phase that renames them; the handoff's `README.md` is not edited (it is the handoff, not our doc).
- **Git conduct per `CLAUDE.md`:** stage by path, Conventional Commits under 70 characters (scope `site`), no phase or slice prefixes, no trailers, never push. The commit and phase gating is the one in Working Loop below.

**Locked decisions.** Routine calls made at plan time so no slice reopens them. Each phase appends the ones it exercises to `DOCS/decisions/playground-bench.md`.

## Working Loop

The execution agent follows this loop every session without exception:

### On Cold Start

1. Read this file (`DOCS/PLANS_PROMPT.md`) in full.
2. Read `DOCS/STATUS.md` (if it exists). The latest entry defines what was last shipped and what comes next.
3. Run `git log --oneline -10` and `git status` in this worktree. If STATUS claims a slice is committed but it does not appear in `git log`, it has not been committed — **do not begin a new slice**. Stop and say so.
4. Read the active phase plan (`DOCS/PLANS/PHASE_<N>_<name>.md`) for the current phase.
5. Implement the next slice per the phase plan. Do not start a second slice until the first is reviewed and committed.

### Each Slice

1. Implement the full slice as specified. Do not stop mid-slice.
2. Run the gates for what the slice touched, in `site/`: `bun test`, `bun --bun run typecheck`, `bun --bun run build`, `bun run bundle`. Do not ship a slice that breaks a gate.
3. Append a STATUS entry (template below).
4. Stage the slice's files (`git add <files>`), by path.
5. **Phases 0–2:** display the proposed commit message and **stop**; wait for explicit human approval before running `git commit`. **Phase 3 onward:** commit the slice without asking, one Conventional Commit per slice, and stop only before the first slice of a new phase to ask whether to begin it. This is the standing gating the human set for this project's plans.

### Git Rules

- Read-only git commands (`status`, `log`, `diff`) are encouraged for situational awareness.
- **Committing:** only at the end of a slice, only the slice's files, staged by path first so the diff can be inspected in any git client. Phases 0–2 wait for approval per slice; later phases commit per slice and ask per phase, as above.
- Do **not** push, force-push, amend, rebase, reset, delete branches, or run any other write `git` or `gh` command under any circumstances. The PR from `playground-bench` into `main` is the human's, and the plan bundle is archived before it (decision 3 and `DOCS/prompts/ARCHIVE.md`).

## Recurring Traps

Add an entry here during execution whenever a non-obvious constraint surfaces — in the same slice that hit it, under the group it belongs to — and name it in that slice's STATUS entry `Notes:` line.

**The island and its tests**

- For small updates and minor fixes, the human asked to use the existing tests/build checks rather than restarting the Chrome setup. Reserve browser automation for visual checks that need it, such as the final sweep.
- After the settings review, the footer holds Compile and Editor only. Schematic owns its preview controls, Truth owns the input-bit cap, and Data/memory own the value base. Editor preferences live in their own envelope field and never schedule a compile.

- `island-smoke.test.ts` reaches 61 `.pg-*` selectors and ids by name. Every slice that renames or removes markup updates the walk in the same slice; a green `bun test` without a fresh `bun --bun run build` proves nothing about the island (the smoke skips without `dist/`).
- `Playground.astro`'s `init` reads elements once by selector at the top (`el.querySelector`); an element moved out of the island's root (the nav, once `Base.astro` yields it) must still be inside the element `init` receives, or be handed in. Keep the bench's whole frame inside the island's root element.
- The store's `normalize` resets everything on a version mismatch. Never bump `STORE_VERSION` without the migrator of decision 5 in the same slice, and test the migration on a literal recorded envelope, not one built from `defaultEnvelope()`.

**Layout**

- `[data-layout='app']` keeps `overflow: hidden` on the body; a grid item defaults to `min-height: auto`, so every row of the frame that holds a scrolling region needs `min-height: 0` (`minmax(0, 1fr)`), or the bottom of the page becomes unreachable with no scrollbar anywhere (the failure the app-layout decision records).
- The `hidden` attribute loses to any `display` rule of higher specificity; the bench's rules on popovers, panels and the drawer keep the `[hidden]` override idiom `global.css:632` uses.
- `.lc-mount` is shared with `LiveCanvas.astro` on `/` and `/gallery`; the sized mount of decision 9 is `.pg-sim-mount`, never the shared class.

**The switcher**

- Early version-2 envelopes already contain the old catalogue tier ids. Map them in workspace normalization as well as on the v1 upgrade path; a v1-only change misses readers of the bench branch.
- Search must see collapsed groups without persisting their temporary expansion. Filter the fully expanded data first, then apply the search-only expansion set, so collapsing a matching group leaves its heading available to reopen.
- The store's save-time `skipped` note says a source stays open. A refused import creates nothing; use `describeNote(note, 'import')` for that context.

**The drawer**

- Phase 0 already added `unit: 'px'` to the splitter. Phase 6 extends it with `pane: 'second'` and a usable-span measurement; callbacks remain numeric in the configured unit, not the obsolete phase spec's object shape.
- The closed terminal line opens on focus. Return focus to its Console button when closing, or the return itself reopens the drawer. Center the splitter's hit band on the bordered row edge so a drag does not acquire a one-pixel offset.
- Memory headers are rebuilt. Their settings controls need delegated change events, and a jump must force its redraw past the focused-text-field guard. Closed drawers skip memory reads.
- After the Phase 6 review, Schematic hides the whole console/memory row. Its track is zero and the status line is pinned to row 4; Live and Truth restore the drawer state. Include this human override when checking the Schematic board.
- The collapsed line depends on readiness as well as transcript changes. The handshake can paint before the session is marked live, so `refreshConsoleGate` repaints the line too; dropping a session refreshes that gate.

**The canvas**

- Restoring an open Data panel can run before the simulator record exists. Use the deferred `hooks.onDataOpen`, as Live uses `hooks.onLive`; artifact delivery fills the panel afterward.
- Live and Data can request a session for the same artifact concurrently. `ensureSession` shares its pending build by bytes; Data row handlers also rebuild when session identity changes, even if the pin shape does not.

- With `viewport: 'parent'` the renderer sizes to the mount; a mount with no height renders nothing and throws nothing. The mount's height comes from the region's grid, not from the canvas.
- `fit()` after a rebuild must run after the mount has its size; a theme flip rebuilds the canvas (`buildCanvas`), so the refit belongs there, once.

**The compiler's replies**

- The truth-table request carries `format` from the settings today and `runTruth` always `JSON.parse`s the reply; `libcirc.wasm` returns markdown or CSV text for those values. Pin the request to `json` and keep `format` for the copy buttons only.
- The truth JSON prints decimal under `value_format: binary` (`lib/truth_table/json.zig:74`); spell cells on the site, never trust the reply's spelling.
- The analyze reply has symbols, not nets; a footer stat named `nets` cannot be computed from it.

**Copy**

- The boards' copy is illustrative; take labels and hints, never numbers. Every new string goes past the Strunk & White check before it ships.
