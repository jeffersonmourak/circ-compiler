# playground

The entries below record the decisions of the playground-v2 initiative (the site's `/playground` as a workbench: editor, tabs, layout, workspace, source linking, settings, live editors). The fifteen decisions locked at plan time are in `DOCS/PLANS_PROMPT.md`; each phase appends the ones it exercises here as it ships them. The library half of the browser story is in [libcirc.md](libcirc.md).

### The compile fast path resolves implicit builtins

**Decision.** `lib/libcirc/frontend.zig`'s `.project_if_imports` route — the compile and `--emit-zig` fast path — takes the project pipeline when the root declares an import **or** instantiates a built-in macro (`usesBuiltinMacro`: any `.unresolved_name` component in the single-module IR whose name is one of `or`, `nand`, `nor`, `xor`, `xnor`). A macro-free, import-free root still skips the import scan. The predicate scans the resolved IR rather than `ast_file.components[]`, so an anonymous nested instance (`wire w(in = xor(...).out)`) counts. `--inspect` stays `.single_module` and still reports `E001` for an unimported built-in; `tests/fixtures/expected-inspect/canonical_full_adder_root.txt` pins that.

**Rationale.** Preview, truth table, sim and analyze already took the project route, so a single file using `xor` previewed and tabulated fine but returned `E001` from `circ_compile` — the playground's Simulate tab went empty for the tour's own half-adder once the reader deleted the import line the tour calls optional. One predicate fixes the library and the CLI together (both select the route through the same enum), adds no diagnostic (`W003` already skips implicit builtins), and keeps the perf guard: `stress_grid_10x10.circ` contains no macro and stays on the fast path.

**Alternatives.** A site-only hint (never produces an artifact); rewriting the request's `files` in the playground (forks the interchange format and breaks line mapping); `compile → .project` unconditionally (leaves the CLI on the old behaviour and needs a byte-equality spike between the two serializers); a new `options.route` key (unknown keys are status 2, so the site could not send it against the committed module).

**Known remainder.** An anonymous-position built-in is routed correctly but does not compile yet: `resolve_bodies.specializeCallSites` pairs AST instances to IR components positionally over `ast_file.components`, never visiting the anonymous components the resolver appends afterwards, so the parametric built-in falls back to its stub module and validation reports `E012` on `a`, `b` and `out`. `tests/fixtures/circuits/builtin_xor_anonymous.circ` pins the route (no `E001`) and nothing more; closing the gap renumbers specialization ids and is a separate initiative.

### The JavaScript budget is per page and gzip is the gate

**Decision.** `bun run bundle` (`site/scripts/check-bundle.ts`, run after `bun --bun run build`) walks every `dist/**/*.html`, seeds the page's eager module graph from its `<script type="module" src>` and `<link rel="modulepreload" href>` tags, follows the built chunks' static imports transitively, and sums raw and gzip bytes — gzip per file (each chunk is its own HTTP response), never over a concatenation. Ceilings live in the committed `site/bundle-budget.json`: `default` `{ gzip: 10240 }` for every route, `routes["/playground"]` `{ raw: 368640, gzip: 122880 }`; `baseline` records the measurement at the time the file was written and never gates. Chunks reachable only through `import()` and inline `<script>` bytes are reported, not gated. The script exits 1 over budget, and also when `/playground` reaches no chunk beyond its seeds — a walker that follows nothing would pass vacuously. A build-free companion test, `site/test/bundle-graph.test.ts`, asserts that nothing reachable from `Base.astro`, `Nav.astro` or `Footer.astro` imports `@codemirror/*`, `@lezer/*` or `codemirror`. A ceiling is never raised silently: any raise is argued in `DOCS/STATUS.md` with the measured number and lands as a `routes` override, never by moving `default`.

**Rationale.** Phase 1 puts CodeMirror on the playground; the pages that do not need it (`/`, `/reference/*`, `/download`) must not pay for it, and "must not" needs a red gate rather than a review habit. Astro emits no `modulepreload` tags for a static build, so the chunk scanner is the only way past each page's entry script, which is why non-vacuity is an exit-1 condition and why the scanner is written for esbuild-minified syntax (`import{a as b}from"./x.js"`).

**Alternatives.** Vite's build manifest or `rollup-plugin-visualizer` (a dependency and a different number, not what the page loads); gating a single total across the site (hides a leak into a light page behind the playground's own weight); gating raw bytes (gzip is what the network transfers).

### The editor is CodeMirror 6 with a hand-written StreamLanguage

**Decision.** `/playground`'s `<textarea>` becomes a CodeMirror 6 editor built from six hand-picked, **exact-pinned** packages — `@codemirror/state 6.7.4`, `@codemirror/view 6.43.11`, `@codemirror/language 6.12.4`, `@codemirror/commands 6.11.0`, `@codemirror/lint 6.9.7`, `@lezer/highlight 1.2.3` — never the `codemirror` meta-package, and never `@codemirror/autocomplete` or `@codemirror/search`. `@lezer/highlight` is a direct dependency, not a transitive one: `tags` is imported by name when the `HighlightStyle` is built. The circ mode is a `StreamLanguage` over a hand-written tokenizer, not a Lezer grammar. `site/test/codemirror-pin.test.ts` is the gate: every version is a bare `x.y.z` in `site/package.json` and resolves at that same version in `site/bun.lock`, and none of the three forbidden packages is a dependency. The whole editor lives in one module, `site/src/scripts/circ-editor.ts`, which nothing imports statically. The keymap is hand-rolled from individual commands (`indentMore`/`indentLess` on Tab, `toggleComment` on `Mod-/`, `toggleTabFocusMode` on `Ctrl-m` / `Shift-Alt-m`, `undo`/`redo`) instead of `defaultKeymap` + `historyKeymap`; `history()` is kept, because per-file undo is a `StateField`.

**Rationale.** The meta-package pulls autocomplete, search and lint in unconditionally, and none of the three is in this initiative's scope; pinning exactly is what makes a phase plan whose every CodeMirror name was read out of a specific `.d.ts` still true after the next `bun install`. A Lezer grammar would need `@lezer/generator` as a build step and a generated file to keep in sync with `circ-lang.mjs`; circ's token set is a dozen regexes. The keymap split is the pre-agreed 20 % rule firing: with `defaultKeymap` the chunk measured 98,646 bytes gzip against a 122,880-byte ceiling (80.3 %, inside the band), and importing `defaultKeymap` retains nearly every command in the package. Hand-rolling it costs 4,276 gzip bytes less and no accessibility: Backspace, Delete and Enter still work unbound (the view translates them from `beforeinput`), and `Ctrl-m` is bound exactly as `defaultKeymap` binds it, so Tab is never a keyboard trap.

**Alternatives.** Monaco (a megabyte, a worker of its own, and a DOM framework); a React wrapper (no framework on this site); the `codemirror` meta-package (three unwanted packages); caret ranges (a minor bump silently invalidates the verified API surface); dropping `@codemirror/commands` entirely (its `historyField` *is* the per-file undo Phase 2 is built on).

### The editor chunk loads on idle, not on interaction

**Decision.** `site/src/scripts/circ-editor.ts` is reached only through a dynamic `import()`, fired from `requestIdleCallback` (falling back to `setTimeout(…, 0)`) after `/playground` paints — not from a first click or focus. Until it resolves the server-rendered `<textarea>` is the live editing surface and `state.source` tracks it; on resolve the editor is handed `state.source`, the textarea is removed and the mount is unhidden; on reject the status line reads `Rich editor unavailable; using the plain text box.` and the textarea stays. This is a **recorded exception** to `DOCS/PLANS_PROMPT.md`'s "nothing heavy loads before interaction", and it does not extend to `libcirc.wasm`: `ensureReady()` keeps its first-interaction gate, now on the editor host's `focusin`. Measured on the slice that shipped it: the chunk is 289,367 bytes raw / 94,370 gzip, and it never enters a page's eager module graph — `/playground`'s gated numbers stayed at 11,857 raw / 5,052 gzip, and `bun run bundle` reports the chunk as an ungated informational line. No budget row is added for it.

**Rationale.** On `/playground` the editor *is* the page. A first-focus gate would show a bare textarea to every visitor who reads before typing, which is the one thing the editor exists to remove, and the chunk is the only heavy thing here whose absence a reader cannot see. Idle time is free by construction, and the textarea fallback means a failed or blocked chunk costs the visitor nothing but colour. The exception is bounded to this page: Phase 7's `<LiveEditor>` in the docs inherits none of it and gates its own activation.

**Alternatives.** Eager import (puts ~92 KB gzip in the page's gated graph for a reader who may never type); first-focus (the regression above); an idle *preload* plus first-focus mount (two mechanisms for one chunk, and the mount still costs a frame at the worst moment); gating the chunk in `bundle-budget.json` (the budget is keyed by route and gates eager graphs only — a lazy row is reported, never gated).

### One token table, two consumers

**Decision.** `site/src/utils/circ-tokens.mjs` is the single source of circ's token vocabulary: `DECLARATION_KEYWORDS`, `BUILTIN_TYPES`, `OPERATORS`, the `alternation()` that turns a word list into `\b(a|b|c)\b`, and the pure tokenizer `nextToken(line, pos, state)` / `tokenizeLine(line, state)`. `site/src/utils/circ-lang.mjs` builds its `keyword` and `type` `match` strings from `KEYWORD_MATCH` / `BUILTIN_MATCH` instead of carrying hand-written literals, and `site/src/scripts/circ-editor.ts`'s `circStreamParser` calls `nextToken` once per token; nothing else about the grammar object changes, so `astro.config.mjs` and `CodePreview.astro` keep working unchanged. **This is the bug fix:** the hand-written builtin list was `\b(and|not|wire|led|or|nand|nor|xor|xnor|bus)\b` — `rom` and `ram` were missing, so every memory in every docs code block on the site rendered unhighlighted. The three operator scopes deliberately stay three hand-written TextMate literals (`connection`, and the two `operator` patterns): they carry three different scope names and three different regex escapings, so collapsing them into one alternation would be wrong. `site/test/circ-tokens.test.ts` pins the two grammars against each other instead — each entry of `OPERATORS` is matched by exactly one of the three patterns and each pattern by exactly one operator, so an operator cannot be added to one grammar and missed by the other. `input_pin` / `output_pin` are **not** in `BUILTIN_TYPES`, and `circ-tokens.mjs`'s header records why. The file stays `.mjs` because `astro.config.mjs` reaches it through `circ-lang.mjs`, and it is the first `.mjs` under `site/src/utils/` to carry JSDoc types.

**Rationale.** Two grammars for one language drift, and this one already had: the same twelve primitives the compiler accepts were spelled ten times in one file and nowhere else, and nothing could have caught it. A shared table makes the drift impossible for the vocabulary and a test the only remaining risk for the shapes. Keeping the tokenizer pure and CodeMirror-free is what lets `bun test` prove the property that actually matters in the browser — `nextToken` always advances, which is the precondition `@codemirror/language`'s `readToken` enforces by throwing "Stream parser failed to advance stream." — in a phase whose manual checklist is recorded unrun.

**Alternatives.** Generating `circ.tmLanguage.json` from the table (the vendored copy lives in another repository, `https://github.com/jeffersonmourak/circ-lsp`, which this repo cannot edit — the header comment now points there instead of at a `tools/circ-lsp/` path that never existed in this tree); a Lezer grammar (a build step and a generated file to keep in sync, for a dozen regexes); driving the editor off the TextMate grammar itself (a regex engine and a scope→tag mapper in the page, to reuse eleven patterns); one alternation for all three operator scopes (loses the scopes).

### The editor palette is derived from the shiki themes

**Decision.** `site/src/utils/circ-editor-theme.ts` resolves the editor's token colours out of the same `shikiLight` / `shikiDark` objects the docs code blocks use (`site/src/utils/shiki-themes.mjs`), through an eleven-entry `TAG_SCOPES` table mapping each CodeMirror tag to one TextMate scope. `scopeStyle` takes the **last** `tokenColors` entry naming that scope or a dotted prefix of it, which is TextMate's own precedence and what makes `keyword.operator` resolve to the accent rather than to `keyword`'s green; a scope with no entry throws rather than falling back. Shiki's `settings.fontStyle` is split at derivation time — `bold` becomes `fontWeight`, `italic` becomes `fontStyle`, `underline` becomes `textDecoration`, and any other word throws. The chrome (background, foreground, gutters, caret, selection, active line) comes from the theme's own `colors` plus the site's CSS variables. `circ-editor.ts` holds one `Compartment` carrying `EditorView.theme(chrome, { dark })` and `syntaxHighlighting(HighlightStyle.define(specs))` together, and a theme flip reconfigures it in place; the view is never destroyed, so cursor, scroll and undo history survive.

**Rationale.** A reader who sees `xor` green in a `/reference` code block and a different green in the playground editor learns that one of them is wrong. One derivation with a throwing lookup is what keeps them equal, and it fails loudly when `shiki-themes.mjs` moves. The `fontStyle` split is not cosmetic: `HighlightStyle.define` passes every non-`tag` key to style-mod as a CSS property, which kebab-cases it, so a pass-through would emit `font-style: bold` — invalid CSS that browsers drop in silence, on `keyword`, the most prominent token class in the file.

**Why a fourth module** where decision 15 named three. `createEditor` builds real DOM nodes unconditionally and `bun test` has no `document`, so the wiring in `circ-editor.ts` cannot be exercised headlessly. The palette derivation is exactly the behaviour that must not drift, and a pure module with no CodeMirror import is the only way a test can prove it does not; it also keeps `circ-editor.ts` a thin wiring file. `site/test/circ-editor-theme.test.ts` pins every colour, the prefix precedence, the totality of the palette over every tag the tokenizer emits across all 17 shipped sources, and the `fontStyle` split.

**Alternatives.** Hand-written CodeMirror colours (drift by construction); importing `@lezer/highlight` into the derivation and returning real `Tag` objects (couples the pure module to CodeMirror for nothing — `circ-editor.ts` resolves the tag names instead); re-theming by destroying and rebuilding the view (loses the cursor and the undo history on every toggle).

### Analyze offsets are mapped in a pure module

**Decision.** `site/src/scripts/circ-diagnostics.ts` owns every conversion between the compiler's coordinates and the editor's: 1-based **byte** columns become UTF-16 offsets through `byteColToUtf16`, and file-local line numbers become combined-document lines through `SplitFile.startLine`. `mapDiagnostics(doc, files, analysis)` returns one `MappedDiagnostic` per analyze diagnostic, in order, with a **nullable** span — a diagnostic blamed on a file with no editor buffer (`<builtin>/…`, or anything outside `/playground/`) keeps its row, carrying the raw path and the compiler's own file-local position, and `toLintDiagnostics` is the only place such rows are dropped. Spans clamp into `[0, doc.length]`, never invert, never split a surrogate pair, and widen by one code point when empty. The module imports no CodeMirror package, so `bun test` drives it against the committed `libcirc.wasm` with no browser.

**Both diagnostics producers go through it.** The playground has two: the analyze reply, and the status-1 compile reply, which carries its own `files[]` and must be mapped as itself rather than against the analyze result it replaces. Each one calls the same `publishDiagnostics(snapshot, analysis)`.

**The staleness guard.** `fire()` captures `const snapshot = state.source` before building the request and maps against that string. The existing `state.gen` check only fires once a *later* run has started, which cannot happen until the debounce elapses, so a reply can land after the reader has typed on. `@codemirror/lint` maps registered diagnostics forward through subsequent changes and has no way to know they were computed against an older document, so `editor.setDiagnostics` is **skipped entirely** when `snapshot !== state.source`; a fresher run is already scheduled. The list still renders, because it carries file-local positions, which do not go stale the same way.

**Rationale.** Both conversions are silently wrong when wrong: a byte-column mapper that assumes ASCII, or a mapper that forgets `startLine`, puts the squiggle on real text that is simply not the text the compiler meant. Neither throws, so only a test catches it — which is why the mapping is a pure module and not a closure inside the island.

**Measured, not assumed.** `@codemirror/lint` bakes its squiggle colours into SVG data URIs rather than CSS colour properties, so `circ-editor.ts` rebuilds `.cm-lintRange-error` / `-warning` with its own `underline(color)` instead of trying to recolour them; the lint *gutter* markers keep their defaults, since their colours sit in both a `fill` and a `stroke`. And the validator emits no per-identifier spans: `input b / not n(in=a) / output o(in=n.out)` reports `E004` over the whole declaration `not n(in=a)`, plus `W001` spanning exactly the unused `b`. The plan prompt's "a squiggle under exactly `a`" was wrong about both the code and the span, and the test pins what the compiler actually reports.

### The marker format does not fork; `joinFiles` is its inverse

**Decision.** The playground's interchange format stays one string with `// <name>.circ` line markers, read by `splitFiles`. `site/src/utils/split-files.ts` gains its exact inverse, `joinFiles(files)`, plus `isFileName(name)` — one predicate derived from the same `MARKER` regex, so the tab UI and the splitter cannot disagree about a legal name — and `joinConflicts(files)`, which names the four arrays the format or the request builder cannot represent: a blank non-last body, a marker line after content, an illegal name, and a duplicate name. `SplitFile` now extends a new `NamedFile { name, body }`, and `rootOf` / `requestFor` accept `readonly NamedFile[]`, so a tab array with no `startLine` drives the worker requests unchanged. Tabs, and later persistence and share links, are views over that one string; no second key and no second format is introduced.

**Round trip.** All 17 shipped sources join back byte-identically. Three normalisations are pinned by name rather than left to be discovered: a redundant leading `// main.circ` marker is dropped (but kept when dropping it would promote the next line to a marker), a source whose last line is a marker gains one trailing newline, and a non-canonical marker re-emits canonically because `MARKER` captures neither its inner nor its trailing whitespace.

**Rationale.** Examples, the tour, `compile-content.ts` and the playground already speak this format; a tab model with its own representation would need a converter at every boundary and would drift from the content the site ships. Making the inverse total and its failures enumerable is what lets the UI warn instead of silently losing a file.

**Alternatives.** A JSON tab document (forks the format, breaks `compile-content.ts`); inferring the root from a field instead of position (decision 3 fixes the root as the last file, and reorder is how it changes).

### The last file is the root; reorder is how you change it

**Decision.** `rootOf(files)` remains `files[files.length - 1]`, and the tab strip marks that tab with a `root` badge. There is no root field and none is added: moving a tab past the end is the way to change which file is compiled. `requestFor` roots the request on the same entry, so the model, the badge and the compiler always agree.

**Rationale.** One source of truth beats two that can disagree. A separate root pointer would have to be validated on every add, delete and rename, and a stale pointer compiles the wrong file with no visible cause.

**Alternatives.** A `root` boolean on each tab (two things to keep in sync); a context-menu "set as root" (a hidden mode, invisible in the tab order, and still a second source of truth).
